# Архитектура

[English](../architecture.md)

## Источник истины

Переносимые определения и ресурсы, относящиеся к конкретным навыкам, находятся в
`skills/<name>/`; исходной точкой входа служит `SKILL.source.md`.
`shared/references/` является каноническим источником повторно используемых
контрактов и кода среды выполнения, а `shared/manifest.json` сопоставляет каждый
общий файл с точным путём сборки. `scripts/build_skills.py` подготавливает
самодостаточные навыки в `.build/skills`, не записывая созданные копии в дерево
исходников. В метаданных исходных и собранных навыков нет поля версии.

Семейство рабочих задач показывает границу такого копирования.
`work-item-contract.md` и `work_item.py` копируются в `askme`, `goal`,
`task-prepare`, `task-review` и `task-triage`, а
`work-item-contract.schema.json` - в тот же набор, кроме `task-triage`. Каждый
установленный навык использует собственные копии. Общий валидатор возвращает
строго один из вердиктов: `ready`, `needs_clarification` или `blocked`.
`task-triage` дополнительно получает специализированную среду выполнения для
GitLab. Она хранит адресуемые по содержимому свидетельства и анализ в XDG state,
повторно использует анализ неизменившихся задач и атомарно обновляет стабильные
Markdown-отчёты, не изменяя GitLab.
Все три task skills получают единый валидатор release planning. Triage владеет
свидетельствами о релизах и milestone, review проверяет общий sidecar, а prepare
использует актуальный scoped triage вместо копирования SemVer-политики.

Репозиторий с исходниками не является источником для установки переносимых
навыков и не поставляет для них интерфейс командной строки. Навыки устанавливаются
из дистрибутива GitHub Pages с помощью `skillmate` — установщика-конфигуратора,
поставляемого на PyPI, — или совместимого CLI `skills` (`npx --yes skills@latest`).
`skillmate` размещает каждый выбранный навык по хостам, формирует командные
поверхности и отвечает за модель безопасности «превью — подтверждение»; канал
`skills` ставит переносимые навыки в `.agents/skills` и остаётся совместимым.

`packages/skills/package.json` является внутренним источником версии переносимого
дистрибутива. `scripts/build_distribution.py` создаёт содержимое Pages в
`.build/packages/skills`: стандартные индексы обнаружения, метаданные и файлы
фиксации выпуска, а также по одному адресуемому по SHA-256 архиву с корневым
`SKILL.md` для каждого навыка. Манифест выпуска связывает каждый файл Pages с
тегом, версией, каналом и ревизией исходников. Конвейер по тегу выполняет полную
проверку, публикует и проверяет Pages, загружает `skillmate` на PyPI с тегов
`main` через trusted publishing, а затем создаёт GitHub Release.

После push в `dev` тот же конвейер публикации выполняет полный gate без
стабильного тега. Затем он создаёт техническую prerelease-версию и заменяет
только Pages `/dev`; dev-канал никогда не попадает в реестры пакетов. Каждый
деплой Pages объединяет стабильный корень и `/dev`, поэтому обновление одного
канала сохраняет другой.

## Интеграция с хостами

Переносимые навыки не зависят от конкретного хоста, а каждый опубликованный архив
самодостаточен. `apps/skillmate/` — установщик-конфигуратор и реестр адаптеров.
Он материализует каждый выбранный навык по хостам: Codex читает `.agents/skills/`
и пишет ссылки на навыки как `$name`, Claude читает `.claude/skills/` с командными
поверхностями в `.claude/commands/`, а OpenCode читает `.opencode/skills/`
(глобальный корень — `~/.config/opencode/`) с командными поверхностями в
`.opencode/commands/`. Адаптеры декларативны; добавление хоста не добавляет
переносимым навыкам зависимостей среды выполнения.

Каждый путь записи проходит через один план: превью всех изменений, явное
подтверждение и манифесты владения в `.skillmate/`, которые обнаруживают
коллизии с чужими файлами и сохраняют пользовательские изменения. Изменённый
после установки файл никогда не перезаписывается молча, а его удаление требует
явного `--confirm-drift`.

## Среда выполнения skillmate

`skillmate` — приложение на Python 3.12+ только со стандартной библиотекой.
Модуль дистрибутива читает версионируемый индекс Pages, проверяет контрольную
сумму каждого архива и распаковывает без подмены источника; `--from-checkout`
запускает собственную сборку чекаута и помечает установку как dev. CLI
предоставляет `install`, `update`, `remove`, `doctor` и `status`; каждая
изменяющая команда показывает версионируемый плановый документ и пишет только
после явного подтверждения, а `doctor` и `status` только читают. Фрагменты
конфигурации OpenCode правятся сохраняющими комментарии вставками, которые при
повторе дают побайтово идентичный результат, а конфликты сообщаются, но не
сливаются.

## Инварианты сборки

- Манифест JSON сопоставляет канонические общие входные файлы только с
  объявленными путями сборки.
- Деревья исходников навыков содержат `SKILL.source.md`, не содержат созданный
  `SKILL.md` и зафиксированные в Git файлы по путям назначения из манифеста.
- В метаданных исходных и собранных навыков нет поля версии.
- `--check` проверяет изолированную подготовительную область и сообщает о
  расхождениях артефактов, не меняя исходные файлы.
- Поддерживаемый установщик читает индекс обнаружения Pages, проверяет
  контрольную сумму каждого архива и не запускает сборку на машине пользователя.
- Пути манифеста нормализованы, относительны и ограничены
  `shared/references/` и существующим навыком; символические ссылки в источниках,
  назначениях и исходных каталогах навыков отклоняются.
- Исходники не меняются, а результат сборки заменяется только после полной
  подготовки и проверки.
- Проверки выпуска связывают версию Pages и ревизию исходников с точным тегом;
  публикация продвигает только прошедшие предварительную проверку артефакты и
  проверяет развёрнутый артефакт Pages до создания GitHub Release.
- Dev-публикация выполняет полный gate для push в `dev`, проверяет свой точный
  артефакт Pages и не может обновить стабильный корень Pages.
- Результаты проверки рабочих задач имеют стабильный порядок, а отчёты связаны
  с контрольными суммами задачи и доказательств, поэтому повторная проверка без
  изменений возвращает тот же вердикт.
