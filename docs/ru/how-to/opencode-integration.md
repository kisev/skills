# Интеграция OpenCode

[English](../../how-to/opencode-integration.md)

`@kisev/agentomatic` - необязательный слой для OpenCode. У переносимых
навыков отдельный жизненный цикл: их нужно устанавливать независимо по
[инструкции для переносимых навыков](portable-skills.md).

## Требования и принадлежность

Пакет требует Node.js 22.13+ и OpenCode `>=2.0.0 <2.1.0`.
Приоритет настроек, env, диагностика и машинный вывод описаны в
[общих соглашениях CLI](../reference/cli.md). Существующий мастер настройки сохранён.

| Компонент | Область проекта | Глобальная область |
| - | - | - |
| npm-пакет | `node_modules` проекта | `node_modules` в npm-проекте `~/.config/opencode` |
| Команды | `.opencode/commands` | `~/.config/opencode/commands` |
| Агенты | `.opencode/agents` | `~/.config/opencode/agents` |
| Необязательные обёртки | `.opencode/plugins` | `~/.config/opencode/plugins` |
| Метаданные принадлежности | `.opencode/.agentomatic` | `~/.config/opencode/.agentomatic` |

Пакет и созданные обёртки должны оставаться доступными после завершения работы
установщика. Импорт, загрузка плагина и сценарии жизненного цикла npm не
устанавливают компоненты или переносимые навыки и не меняют конфигурацию OpenCode.

## OpenCode V2

Поддерживаются все патчи минора `2.0.x`. Конкретные версии в
`evals/contracts/opencode-compatibility.json` - выборка для проверок, а не
список разрешённых версий. Пакет и необязательные обёртки используют нативный
entrypoint `setup`, hooks и упорядоченные permissions V2. Runtime и проверок
совместимости с V1 больше нет. Для OpenCode V1 оставайтесь на последнем
стабильном [релизе линейки `11.0.x`](https://github.com/kisev/skills/releases),
а не устанавливайте канал `dev`. V1 и V2 используют общие пути конфигурации;
не запускайте V1 с файлами, переведёнными в нативный формат V2.

После обновления существующей установки просмотрите план upgrade установщика
и подтвердите его, чтобы заменить управляемые обёртки плагинов, затем
перезапустите OpenCode. Старые обёртки, экспортирующие только функцию, не
загружаются в V2. Сохраните обёртки с пользовательскими изменениями:
установщик сообщает о конфликте вместо их перезаписи.

Config setup пишет нативные `plugins` и `permissions` в `opencode.json(c)`.
Основной плагин регистрируется спецификацией реестра с точной версией
(`@kisev/agentomatic@<version>`): OpenCode V2 резолвит голое имя пакета через
dist-tag `latest` в npm и может загрузить другую сборку вместо установленной.
Повторный запуск core-фрагмента перепинивает голую или устаревшую регистрацию
на месте, посторонние записи плагинов не затрагиваются.
Переводятся только разделы, нужные выбранным фрагментам, а не весь конфиг.
Противоречащие друг другу старые и новые разделы показываются как конфликт,
без попытки угадать намерение пользователя. Не регистрируйте пакет дважды.

Для разработки через npm backend в `mise.toml` устанавливается только V2.
`task package:check` проверяет установленные tarball на закреплённом патче,
включая реальную проверку permissions, а также поведение без хоста. Учётные данные моделей
для этих проверок не нужны; установка зависимостей может требовать доступа
к registry.

## Установка

`npm view` показывает версию в реестре; `latest` и `dev` могут сдвинуться до
установки. npx запускает CLI, не устанавливая его глобально. После подтверждения
установки проверьте постоянную зависимость через `npm list` во владеющем
npm-проекте; один dry run ничего не устанавливает.

### Область проекта

Запустите установщик из корня проекта; подтверждённая установка также пропишет
постоянную npm-зависимость в ближайшем npm-проекте:

```shell
cd /path/to/project
# Registry version
npm view --prefer-online @kisev/agentomatic@latest version

# Preview, then confirm the install
npx --yes @kisev/agentomatic@latest install --dry-run
npx --yes @kisev/agentomatic@latest install

# Installed dependency in the owning npm project
npm list @kisev/agentomatic --depth=0
```

Пакет попадает в `node_modules` проекта, а подтверждённые компоненты
размещаются в `.opencode`. Если npm-проекта выше по дереву нет, план сообщит о
необходимости ручного шага вместо создания файлов.

### Глобальная область

Запустите установщик из любого каталога:

```shell
# Registry version
npm view --prefer-online @kisev/agentomatic@latest version

# Preview, then confirm the install
npx --yes @kisev/agentomatic@latest install --global --dry-run
npx --yes @kisev/agentomatic@latest install --global

# Installed dependency, not npm's global CLI prefix
npm list --prefix "$HOME/.config/opencode" @kisev/agentomatic --depth=0
```

Подтверждённая установка владеет npm-проектом в `~/.config/opencode`: при
необходимости создаёт минимальный `package.json` и закрепляет точную
исполняемую версию через `npm install --save-exact`. Подтверждённые компоненты
размещаются в `~/.config/opencode`. Команды только чтения - `status`, `doctor`,
`catalog` и `agent list` - работают из любого каталога в той же явной
форме; `maintenance cleanup` и `uninstall` выполняйте из владеющего npm-проекта через
`npx agentomatic`, где версия исполнения обязана совпадать с установленным
пакетом. В офлайн-окружении зависимость можно поставить вручную:
`npm install --save-exact @kisev/agentomatic`, затем
`npx agentomatic install --dry-run`. Передайте `--no-dependency`, чтобы полностью
пропустить шаг подготовки зависимости.

### Dev-канал

Укажите dist-tag `dev` явно, чтобы закрепить его prerelease-версию:

```shell
# Registry version
npm view --prefer-online @kisev/agentomatic@dev version

# Preview, then confirm the install
npx --yes @kisev/agentomatic@dev install --global --dry-run
npx --yes @kisev/agentomatic@dev install --global

# Installed dependency
npm list --prefix "$HOME/.config/opencode" @kisev/agentomatic --depth=0
```

Каждый успешный push в `dev` публикует уникальную prerelease-версию и перемещает
только dist-tag `dev`. Чтобы вернуться на стабильный канал, повторите команду
стабильного установщика; она перепривяжет зависимость к текущему стабильному
выпуску.

## Выбор компонентов

В TTY команда `install` предлагает адаптеры команд, фиксированных агентов,
плагины и подключение core, затем необязательные пресеты и настройку моделей
и критиков. Изменения профилей остаются в памяти до итогового подтверждения.
Настройку моделей можно пропустить без сброса сохранённых моделей и вариантов.
Повторная установка начинает с сохранённого состава; снятие выбора показывает
удаление управляемых файлов. При первой установке команды навыков и шесть
фиксированных агентов выбраны, обёртка `rtk` тоже. Skill command adapters - это
слеш-команды OpenCode, которые загружают уже установленный одноимённый переносимый
навык. Выбор адаптера не выбирает и не устанавливает навык. В каждой
группе можно выбрать произвольный набор: Up/Down перемещает курсор, Space
переключает элемент, A переключает весь набор, Enter подтверждает, Escape
отменяет.

Вне TTY первая установка требует параметры всех трёх групп; повторный запуск
может использовать сохранённый состав. В этом примере выбраны
три команды, все агенты с фиксированными ролями и ни одна обёртка:

```shell
npx agentomatic install \
  --commands askme,code-review,goal \
  --agents manager,architect,mapper,worker,review,critic \
  --plugins none --dry-run
```

Если вне TTY передан любой параметр выбора, обязательны `--commands`, `--agents`
и `--plugins`. Точные текущие имена можно получить командой:

```shell
npx --yes @kisev/agentomatic@latest catalog --json
```

Доступные обёртки: `rules-injector`, `rtk`, `zed-bell`; `rtk` предварительно
выбрана установщиком. OpenCode автоматически загружает размещённые файлы
обёрток из каталога `plugins`, поэтому запись в массив `plugin` для них не
нужна - он остаётся только для npm-пакета основной интеграции. Явно отключить
обёртку можно параметром `--plugins none`.

## Наблюдаемость сжатия RTK

Обёртка `rtk` сжимает вывод инструмента `shell` длиннее 8000 символов через
внешний RTK CLI, при недоступном бинаре откатывается к усечению head+tail и
дописывает к каждому сжатому выводу маркер
`[rtk: compressed method=...; sizes=...; evidence_complete=false]`.
Классифицированные счётчики событий, экономия в символах и ограниченный список
последних событий хранятся только в
`$XDG_STATE_HOME/opencode/skills/rtk/stats.json` (права 0600) и никогда не
содержат текста вывода команд.

Сводку можно посмотреть командой `/rtk-stats` или в машиночитаемом виде через
проверку `rtk.observability`:

```shell
npx --yes @kisev/agentomatic@latest doctor --json
```

Проверка сообщает о развёртывании обёртки, доступности бинаря RTK, счётчиках
событий, оценке сэкономленных токенов и времени обновления статистики.

## Активация основного плагина

Установщик фиксирует, нужна ли выбранным компонентам основная интеграция.
Подтверждённый `install` с выбранным core выполняет тот же шаг настройки,
что и `configure integration`; `--no-core` отключает плагин, не удаляя npm-зависимость.
`uninstall` тоже предлагает отключение. Пакет также
можно подключить подтверждённой командой `configure integration` или добавить его в
пользовательский массив `plugins` для той же области вручную, сохранив
существующие элементы:

```json
{
  "$schema": "https://opencode.ai/config.json",
  "plugins": ["@kisev/agentomatic"]
}
```

Для области проекта храните пакет в каталоге `node_modules` проекта, а
конфигурацию - в самом проекте. Для глобальной области храните npm-проект и
пользовательскую конфигурацию в `~/.config/opencode`. После активации или
изменения компонентов перезапустите OpenCode.

## Настройка пользовательских конфигов

`configure` открывает меню компонентов, моделей, критиков и интеграции.
`configure components` меняет установленный состав без сброса моделей.
`configure integration` подключает пакет и рекомендованные фрагменты в
пользовательские файлы конфигурации:

```shell
npx agentomatic configure integration --global --dry-run
npx agentomatic configure integration --dry-run
```

В терминале без флагов открываются селекторы целей и фрагментов. Глобальная
область настраивает `~/.config/opencode/opencode.json(c)` и `cli.json`,
`~/.config/kilo/kilo.json(c)` и `tui.json[c]`, `~/.config/mimocode/mimocode.json(c)`
и `tui.json`; область
проекта - только файл `opencode.json(c)` проекта. Вне терминала передайте
`--targets` и `--fragments` явно.

Доступные фрагменты:

| Фрагмент | Цели | Эффект |
| - | - | - |
| `core-plugin` | opencode | Добавляет `$schema` и регистрирует `@kisev/agentomatic` в `plugins` |
| `core-disable` | opencode | Убирает только регистрации agentomatic/старого пакета, сохраняя остальные плагины и пресеты; несовместим с `core-plugin` |
| `skills-state-permissions` | opencode, kilo, mimo | Разрешает чтение, правки и доступ к внешнему каталогу для штатного состояния навыков в `~/.local/state/agent-skills/**`; OpenCode также разрешает чтение и доступ к внешнему каталогу в каноническом дереве переносимых навыков `~/.agents/skills/**` и в устаревшем `~/.config/opencode/skills/**`, а также перечисление самих этих корней и каталога `~/.agents` (действие `external_directory`), чтобы сканы каталогов (glob/list) не запрашивали доступ. OpenCode использует упорядоченные `permissions`, Kilo/MiMo сохраняют карты `permission` |
| `secrets-guard` | opencode, kilo, mimo | Запрещает чтение и изменение распространённых файлов секретов (`.env*`, ключи, учётные данные) |
| `kilo-display` | kilo | Разворачивает блоки reasoning, терминала, правок и инструментов |
| `tui-schema` | opencode, kilo, mimo | OpenCode пишет глобальный `cli.json` со схемой V2, `theme.name: ayu` и нативными ID биндов. Kilo/MiMo сохраняют свои TUI-форматы, `theme: ayu`, stacked diffs и прежние ID биндов |

Комментарии и посторонние записи сохраняются. В OpenCode затронутый старый
раздел `plugin`, `permission` или отдельный `tools` переводится в нативный V2.
Скалярные permissions становятся wildcard-правилами, а старые имена действий
заменяются на `shell`, `subagent` или `edit`. Порядок существующих правил
сохраняется; новые правила пресета добавляются после них. Различающиеся старые
и новые разделы, совместные старые `tools` и `permission`, неподдерживаемые
старые действия и явные правила, противоречащие пресету, дают конфликт, а не
незаметную перезапись. Kilo/MiMo по-прежнему расширяют скалярные карты
permissions, сохраняя исходное значение в `"*"`.
Фрагменты, которые нельзя аккуратно влить, показываются как конфликты. CLI
блокирует применение, пока конфликт не устранён или фрагмент не исключён из выбора.
Настройка требует предпросмотра, явного подтверждения и перезапуска затронутого
приложения. Выбор подключения сохраняется для повторной установки и repair.
При ошибке конфигурационного шага install сообщает, какие предыдущие этапы
завершились и как продолжить через `configure integration`.

V2 больше не читает `tui.json` как настройки терминала. Если этот файл есть,
а `cli.json` ещё нет, сначала запустите V2: встроенная миграция сохранит
предпочтения. Затем повторите настройку. Пресет сохраняет существующие значения
`cli.json` и не подменяет старый stacked-diff или удалённые бинды другими
настройками V2. Настроек терминала на уровне проекта нет. Эта миграция V2
не затрагивает файлы Kilo и MiMo.

`lsp-preset` удалён: V2 принимает `lsp`, но сейчас не запускает language servers.
Существующие пользовательские записи `lsp` остаются без изменений; для проверки
используйте lint, typecheck или компилятор проекта.

Выбор `core-plugin` может обращаться к npm и менять `package.json`,
`package-lock.json` и `node_modules`; предпросмотр показывает план зависимости.
Ошибка npm сообщается отдельно от завершённой транзакции конфигурации.
Устраните ошибку зависимости и повторите предпросмотр. `install --no-dependency`
отключает provisioning на всём пути установки.

Предпросмотр config не создаёт блокировки и не восстанавливает прерванные транзакции.
Интерактивное применение связывает показанный план с одноразовым подтверждением на
пять минут в том же процессе; изменившиеся байты требуют нового предпросмотра.
Отдельный `--dry-run` не выдаёт переносимую между процессами квитанцию; `--yes`
разрешает новый план. Для прерванной транзакции config проверьте и подтвердите восстановление:

```shell
npx agentomatic maintenance recover --global --dry-run
npx agentomatic maintenance recover --global
```

Для области проекта уберите `--global`. Восстановление отменяет прерванную транзакцию
до нового предпросмотра config; изменение данных восстановления требует повторного предпросмотра.

## Предварительный просмотр и подтверждение

Каждое изменение начинается с `--dry-run`. Предварительный просмотр только
читает: он показывает операции, конфликты и необходимость перезапуска и
завершается подсказкой Apply для той же команды с указанием на интерактивное
подтверждение и параметр `--yes` вне терминала. Если cleanup обнаруживает
изменённые управляемые файлы или конфликты принадлежности, продолжение
блокируется: подтверждение применения не предлагается. Сначала установите или
обновите текущий пакет, примените план установщика, затем повторите
cleanup; конфликты принадлежности нужно разрешить вручную.

```shell
npx agentomatic install --dry-run
```

Последовательность для OpenCode - один запуск install: мастер спрашивает адаптеры
команд, фиксированных агентов, плагины, подключение core, необязательные пресеты,
модели и дополнительных критиков. Одно подтверждение применяет компоненты и профили,
вписывает фрагмент `core-plugin` в пользовательский конфиг и прописывает
постоянную npm-зависимость в `~/.config/opencode`, которая держит глобальный
плагин доступным. Шаг с зависимостью тем же проходом удаляет легаси-зависимость
`@kisev/skills-opencode`. Неинтерактивные запуски передают `--core` (или
`--no-core`) вместе с явными флагами выбора. `configure integration` остаётся полным
менеджером фрагментов для всех целей; применение её фрагмента `core-plugin`
прописывает ту же зависимость, если установщик её пропустил. Перед каждым
подтверждённым применением config предыдущее содержимое каждого изменяемого
пользовательского файла уходит в архив пакета
(`~/.local/share/opencode/agentomatic/archive`) — content-addressed и с
дедупликацией; `doctor --json` показывает последний снапшот в `config.backups`. Команды с областью по умолчанию работают с текущим
каталогом; добавьте `--global` один раз для глобального состояния. Удалённый
параметр `--scope` не поддерживается. Компоненты и профили, npm и конфигурация
приложений применяются отдельными этапами, а не одной атомарной транзакцией.
При ошибке следующего этапа завершённые изменения остаются на месте; отчёт
показывает продолжение. Перед повтором проверьте `status`.

Без `--dry-run` изменение запрашивает согласие напрямую. В TTY сначала
запускаются интерактивные мастера выбора, затем печатается сводка плана, и
записи нет до ответа Yes на итоговый вопрос "Apply the displayed changes?". Вне TTY
передайте явные параметры выбора вместе с `--yes`; без `--yes` команда
завершается подсказкой о предпросмотре или явном подтверждении. Предпросмотр не
создаёт блокировки и не восстанавливает журналы автоматически. Изменение исходных
файлов делает подтверждённый план устаревшим; каждый локальный этап поддерживает rollback.

## Состояние установки

```shell
npx agentomatic status --global
npx agentomatic status --global --json
```

`status` показывает состав установки, подключение плагина, npm-зависимость,
сохранённые модели и пул критиков. `agent list` выводит таблицу профилей;
`not-installed` означает невыбранную роль, а не повреждение.
`catalog --json` описывает возможности запущенного пакета, а не этой установки.

## `doctor`

`doctor` считывает сведения об интеграции, не создавая состояние, не выполняя
восстановление по журналам и не запуская плагины или LSP-серверы:

```shell
npx --yes @kisev/agentomatic@latest doctor
npx --yes @kisev/agentomatic@latest doctor --json
```

Отчёт содержит версии, принадлежность, отклонения, коллизии, количество архивов,
представления конфигурации со скрытыми значениями, сводки состояния выполнения и
сведения о LSP с отметкой, что V2 его не поддерживает, а не считает активным.
Отсутствие LSP-бинарников не считается ошибкой зависимостей OpenCode.
Проекции читают JSON и JSONC. Исходная конфигурация, значения окружения, учётные данные и
секреты не сериализуются. Код завершения `0` означает отсутствие
проблем, `1` - наличие замечаний, а `2` - недопустимые входные данные или
неполную проверку.

## Обновление

Обновление выполняется текущим стабильным установщиком с той же областью и
нужным набором компонентов, после чего перезапустите OpenCode:

```shell
npx --yes @kisev/agentomatic@latest install --global --dry-run
```

Повторите команду установки без `--dry-run` и подтвердите сводку плана;
подтверждённая установка перепривязывает постоянную зависимость к исполняемой
версии.
Установщик обновляет только файлы, для которых совпадают сохранённые сведения о
принадлежности и контрольная сумма SHA-256. Пользовательские или изменённые
управляемые файлы остаются конфликтами. Обновление пакета не сбрасывает выбранные
модели и варианты агентов, дополнительных критиков или сохранённую конфигурацию
профилей.

## Обслуживание

`maintenance cleanup` классифицирует текущие и прежние команды пакета, плагины, агенты и
метаданные установки в одной области:

```shell
npx agentomatic maintenance cleanup --dry-run
npx agentomatic maintenance cleanup --yes
npx agentomatic maintenance cleanup --global --dry-run --json
npx agentomatic maintenance repair --global --dry-run
```

Перед cleanup обновите пакет через его установщик. Переносимыми навыками
управляйте отдельно через `npx --yes skills@latest update` или
`npx --yes skills@latest remove`: их каталоги и lock-файлы не влияют на план,
конфликты или операции cleanup.

После подтверждения cleanup сохраняет текущие байты в закрытом XDG-архиве с
адресацией по содержимому. Компоненты пакета удаляются транзакционно.
Пользовательские и неизвестные компоненты пакета, а также симлинки, небезопасные
и неоднозначные пути остаются без изменений. Пустой план сообщает, что изменения
cleanup не требуются, и не предлагает применение. Переносимые навыки, их
lock-файлы, рабочие деревья и runtime state
сохраняются. Архив можно просматривать через `doctor`; команд `restore` и `purge`
нет.

`maintenance repair` восстанавливает отсутствующие выбранные компоненты и
перегенерирует управляемые файлы из сохранённых моделей. Невыбранные роли не
добавляются; изменённые байты не перезаписываются. Перед повтором устраните
конфликты принадлежности и содержимого; повреждение только прав доступа при
точном совпадении байтов можно исправить. Без сохранённой установки используйте
`install`. `maintenance recover` восстанавливает журнал только после подтверждения
его путей и digest, затем требует нового предпросмотра.

## Управление агентами

CLI напрямую управляет моделями агентов с фиксированными ролями и дополнительными
критиками без обращения к LLM:

```shell
npx --yes @kisev/agentomatic@latest agent list --global
npx agentomatic configure agent manager --global --dry-run
npx agentomatic configure agent worker --global --model openai/gpt-5 --variant high --dry-run
npx agentomatic configure critics --global
npx agentomatic agent add-critic security --global --model anthropic/claude-sonnet-4-6 --dry-run
npx agentomatic agent remove critic-security --global --dry-run
```

Фиксированные роли сохраняют имена и инструкции; списки разрешённого делегирования
отражают выбранные роли и пул критиков. Сохранение модели неустановленной роли
не устанавливает её. Дополнительные критики используют
`critic-<safe-suffix>`; `agent remove` не удаляет фиксированные роли. Для каждого изменения действует тот же контракт
предварительного просмотра и подтверждения.

Дополнительные профили не обязательны для независимого ревью в скиллах.
`code-review` спрашивает, каких доступных критиков и сколько использовать.
Если их нет, текущий агент запускает обычных независимых нативных сабагентов.
Core plugin проверяет routing receipts и структурированные отчёты для профилей
пакета и явно маршрутизированных вызовов, но не для обычных нативных сабагентов.
Для такого запуска не нужны установка агента или обход через `opencode run`.
Маршрутизированный независимый критик может вернуть `review_report` или квитанцию
code-review; вызывающий агент сохраняет реальные идентификаторы нативного запуска
в черновике reviewmatic. Параллельные вызовы имеют отдельные привязки. Срок
квитанции проверяется до запуска; начатое ревью не становится недействительным
только потому, что модель работала дольше.
Core plugin передаёт основному агенту и сабагентам реальные идентификаторы текущих
сессий для квитанций; эти данные не разрешают изменения или публикацию.

Файлы агентов используют `permissions` и `provider/model#variant`. CLI сохраняет
отдельные флаги `--model`, `--variant` и выбранные настройки профилей.
Интерактивный выбор моделей читает снимок V2 `/api/model` через `opencode api`:
без обращения к LLM или принудительного обновления каталога. OpenCode может
запустить свою управляемую службу. Если снимок недоступен, мастер попросит
ввести точный provider/model и необязательный вариант текстом, а не прервётся;
неинтерактивные запуски передают `--model` и `--variant` явно.

## `uninstall`

Пакет должен оставаться доступным до удаления его компонентов:

План отдельно показывает компоненты, отключение плагина, удаление npm-зависимости
и сохранённые модели. Отключение предлагается по умолчанию; `--no-disconnect`
сохраняет подключение. Модели сохраняются. Удаление зависимости включается явно
через `--remove-dependency` или вопрос мастера. Остальные пресеты не меняются.

```shell
npx agentomatic uninstall --dry-run
npx agentomatic uninstall --yes
npx agentomatic uninstall --remove-dependency --yes
```

Для глобальной области выполните те же команды с `--global` из постоянного
npm-проекта в `~/.config/opencode` или запустите пакет точной версии из любого
каталога. Сохраняйте доступность пакета до завершения команды, затем перезапустите OpenCode.
`uninstall` архивирует компоненты, чья принадлежность точно
подтверждена манифестом, и сохраняет изменённые файлы как конфликты вместе с
рабочими деревьями, состоянием выполнения и сохранённой конфигурацией профилей.
CLI блокирует небезопасные конфликты до удаления. Команда может изменить только
выбранные регистрации плагина в `opencode.json(c)` и явно удалить зависимость;
переносимые навыки она не удаляет. При ошибке npm завершённые локальные этапы
не откатываются: проверьте `status` и повторите те же параметры uninstall.
Команд `restore` или `purge` для архива нет.

## Границы

- Переносимые навыки и компоненты пакета устанавливаются, обновляются и удаляются
  независимо.
- Команды, соответствующие навыкам, являются простыми адаптерами; поведение
  определяет переносимый навык, который устанавливается отдельно.
- Единственный инструмент пакета - `route`; у него нет слеш-команды.
  Административные операции выполняются через прямой CLI `agentomatic`.
- Подтверждённый `install` с выбранным core добавляет `plugin` в
  `opencode.json` через исполнитель config. `uninstall` сохраняет постороннюю конфигурацию.
- Глобальная область не зависит от текущего рабочего каталога; область проекта
  использует `.opencode` в текущем каталоге.
- Установщик считает своими только файлы, для которых принадлежность подтверждена
  манифестами и точными контрольными суммами.
- npm `latest` обозначает стабильный канал; npm `dev` - явно выбранный
  обновляемый канал разработки, который не определяет следующую stable-версию.
- Пакет распространяется по лицензии MIT. Текущий состав и проверки описаны в
  [инвентаре миграции](../migration-inventory.md) и
  [документе проверки](../verification.md).
