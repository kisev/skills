# Синтетические живые проверки

[English](../../how-to/live-runs-ccr.md)

Живые проверки (скорость 2 модели верификации) отправляют один прогон с
реальной моделью по версионируемому сценарию и проверяют наблюдаемый
результат. Всё зафиксировано: движок и его профиль берутся из файла профиля,
а фикстура, промпт и ассерты — из `evals/live/<сценарий>/`. Профиль по
умолчанию — `evals/live/profile.json` (ccr); `--profile` выбирает другой хост,
не меняя сценарий.

## Предварительные требования

1. Установите [ccr](https://github.com/musistudio/claude-code-router) на
   хосте: `npm install -g @musistudio/claude-code-router`, затем проверьте,
   что `ccr --help` отвечает.
2. Создайте выделенный профиль ccr с именем `skills-tests-claude`
   (`~/.claude-code-router/profiles/skills-tests-claude/`) и выберите его
   маршрутизацию и модель внутри самого профиля — модель никогда не забота
   репозитория. Ключи провайдера остаются на хосте: репозиторий фиксирует
   имена, но никогда креды и модели.
3. Для opencode установите CLI и выберите хостового агента, названного в
   `engine_profile` файла `evals/live/profiles/opencode.json` (по умолчанию
   `build`). Модель и провайдера держит сам агент.
4. Для codex установите CLI и создайте хостовый профиль, названный в
   `engine_profile` файла `evals/live/profiles/codex.json` (по умолчанию
   `live-runs`), в `$CODEX_HOME/live-runs.config.toml` (`~/.codex` по
   умолчанию). Модель и провайдера держит сам профиль.
5. Соберите архивы скиллов один раз: `task generate`.

## Проверка настройки

```shell
task live:preflight
task live:preflight -- --profile evals/live/profiles/opencode.json
task live:preflight -- --profile evals/live/profiles/codex.json
```

Предполёт проверяет файл профиля, CLI хоста, хостовый профиль там, где он
есть, и формат каждого сценария — без единого вызова модели. Каждая красная
строка называет точный ремонт.

## Запуск сценария

```shell
task live:run -- --scenario agents-md-mirror
task live:run -- --scenario agents-md-mirror --variant no-symlink
task live:run -- --scenario mr-review-untrusted --profile evals/live/profiles/opencode.json
task live:run -- --all
```

`--all` прогоняет default-вариант каждого сценария (релизный обход).

Прогон разворачивает фикстуру в изолированный пустой workdir, запускает
движок в сабпроцессе с позитивным allowlist окружения (креда не может
«проехать» ни под каким именем) и с ограниченными правами: правки остаются
внутри подготовленного workdir, а более широкие права инструментам даёт
только поле `allowed_tools` сценария или хостовый агент, никогда общий
обход. Отчёт с хостом, профилем движка, вердиктом и отредактированным
транскриптом оседает в `.build/live-runs/<время>-<сценарий>-<вариант>/`.
Прогон opencode подкладывает проектный конфиг, запрещающий выполнение shell
и сетевые запросы, а прогон codex использует песочницу `workspace-write`;
прогон также снимает отпечаток ограниченного хостового состояния движка до и
после и записывает drift в отчёт — информационное свидетельство сессионных
артефактов, зафиксированная цена реального HOME, а не утечка.

## Межхостовое свидетельство

Запустите текстовые сценарии по одному guided-прогону на хост и по одному
контролю без руководства на хост, прочитайте выводы вручную и запишите
матрицу хостов в отчёты. Полное давление из пяти повторов остаётся на
хосте ccr по умолчанию; межхостовый прогон — свидетельство паритета, а не
второе давление. Хост, у которого нет CLI или хостового профиля, помечается
заблокированным с точным именем; никогда не симулируйте успех и не
подменяйте хост.

## Когда запускать

Один прогон на существенное изменение поведения скилла; полный обход всех
сценариев — перед релизом. Воспроизводимый отказ сначала оседает регрессией
скорости 1, затем сценарий перезапускается в зелёное. Контракт системы — в
чендже `live-runs` под `openspec/changes/`.
