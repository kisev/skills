# Установка и управление навыками

[English](../../how-to/install-skills.md)

`skillmate` — единый установщик-конфигуратор переносимых навыков этого проекта, их командных поверхностей и настройки хостов Codex, Claude и OpenCode в проектной и глобальной областях. По умолчанию он ставит содержимое из версионного дистрибутива GitHub Pages и никогда не подменяет источник догадкой; локальный чекаут — режим только для разработки.

## Предпосылки

- Python 3.12+ и [`uv`](https://docs.astral.sh/uv/) (`uvx skillmate`) либо `pip` (`pip install skillmate`).
- Для режима dev-чекаута: локальный клон этого репозитория с доступными [`mise`](https://mise.jdx.dev/) и [`task`](https://taskfile.dev).

## Установка

Покажите план, затем примените его:

```shell
uvx skillmate install
uvx skillmate install --yes
```

Явно выбирайте хосты и область, когда значения по умолчанию не подходят:

```shell
uvx skillmate install --hosts claude,opencode --scope global --yes
uvx skillmate install --skill commit-msg --skill verification --yes
```

Размещение следует нативным каталогам хостов:

| Хост | Навыки, проект | Навыки, глобально | Команды |
| - | - | - | - |
| Codex | `.agents/skills/` | `~/.agents/skills/` | нет — навыки вызываются как `$name` |
| Claude | `.claude/skills/` | `~/.claude/skills/` | `.claude/commands/*.md` |
| OpenCode | `.opencode/skills/` | `~/.config/opencode/skills/` | `.opencode/commands/*.md` |

Каждый хост получает собственную материализованную копию: каноническое содержимое, к которому применены только диалектные преобразования (Codex пишет ссылки на навыки как `$name`). Установка OpenCode вместе с Claude или Codex приводит к тому, что OpenCode видит те же навыки и через совместимые каталоги; план сообщает об этой дублирующейся видимости, потому что OpenCode не документирует приоритет дубликатов.

Перезапустите хост после установки или обновления, чтобы новые навыки и команды были обнаружены.

## Обновление и закрепление версий

Каждая установка записывает версию дистрибутива, которую она установила. `update` показывает пофайловые изменения и применяет их после подтверждения:

```shell
uvx skillmate update --yes
uvx skillmate update --version <version> --yes
```

## Удаление

Удаление снимает только файлы, которыми владеет skillmate, по хостам и областям:

```shell
uvx skillmate remove --yes
uvx skillmate remove --hosts claude --scope global --yes
```

Файл, изменённый вами после установки, помечается как расходящийся и удаляется только с явным `--confirm-drift`.

## Диагностика

`doctor` читает установки и называет каждую проблему с её ремонтом: отсутствующие файлы, расхождение версий с дистрибутивом, изменённые файлы, устаревшие записи владения и чужие файлы на путях дистрибутива. Он ничего не пишет.

```shell
uvx skillmate doctor
uvx skillmate status
```

## Режим dev-чекаута

Для неопубликованного или экспериментального содержимого установите из рабочего дерева этого репозитория. Режим запускает собственную сборку чекаута (`task distribution:build`) и помечает установку как dev:

```shell
uvx skillmate install --from-checkout /path/to/skills --yes
```

`--from-checkout` и `--version` взаимоисключающи; dev-установка показывает `source: checkout` в `status`.

## Модель безопасности

Каждый путь записи проходит через один план: превью всех изменений, явное подтверждение, манифесты владения, обнаруживающие коллизии с чужими файлами, и сохранение пользовательских изменений. Чужие файлы не трогаются никогда, а изменённый вами после установки файл не перезаписывается молча.

## Канал `npx skills`

Тот же дистрибутив Pages обслуживает CLI `skills` (`npx --yes skills@latest add https://kisev.github.io/skills`). Он устанавливает переносимые навыки в `.agents/skills` и остаётся совместимым; `skillmate` добавляет размещение по хостам, командные поверхности и модель безопасности «превью — подтверждение». В одной области предпочитайте один канал, чтобы не управлять одним навыком дважды.
