# Публикация пакета `skillmate`

[English](../../how-to/pypi-package-lifecycle.md)

`skillmate` — единственный канал публикации этого репозитория: дистрибутив PyPI `skillmate` под учётной записью `kisev`. Этот документ — полное описание жизненного цикла: добавление, версионирование, публикация и выведение — и он описывает ровно один канал. Больше ничего в репозитории не публикует в реестры пакетов.

## Идентичность и расположение

- Дистрибутив, пакет импорта и консольная команда — все называются `skillmate`.
- Источник истины: `apps/skillmate/` (src-разметка hatchling, Python 3.12+).
- Авторитет версии — манифест переносимой версии `packages/skills/package.json`; первый заголовок `CHANGELOG.md` несёт ту же версию. Выравнивание проверяет `task version:check`.

## Добавление или изменение пакета

Переименование дистрибутива, пакета импорта или консольной команды — миграция с сохранением всей полноты, а не правка: она затрагивает имя на PyPI, все записи установок, документацию и руководство по установке. Делайте это только через OpenSpec-чендж.

## Публикация

Публикация автоматизирована и запускается только с тега:

- `.github/workflows/publish.yml` запускается с тегированного коммита. Тег на `main` публикует корень Pages и создаёт GitHub Release; тег на обслуживающей линии `release/vX.Y` создаёт GitHub Release, не трогая корень Pages.
- Загрузка на PyPI использует trusted publishing (GitHub OIDC) с тегов `main`; токен PyPI нигде не хранится. Воркфлоу отказывает незатегированным запускам.
- Каждый успешный push в `dev` публикует prerelease `skillmate`
  `{version}.dev{run}` на PyPI через то же окружение trusted publishing;
  номер прогона общий с dev-версией Pages. Prerelease неизменяемы: сломанный
  помечается yank на странице проекта PyPI и заменяется следующим push. Пока
  стабильного релиза нет, `uvx skillmate` выбирает новейший prerelease; после
  — выбирайте его явно через `uvx --prerelease skillmate`. `--from-checkout`
  остаётся путём без реестра для неопубликованного содержимого.

Релизная дисциплина (зеркала версий, changelog, ворота подтверждения, аннотированные теги) живёт в проектном навыке `pypi-package-lifecycle` и релизном flow в `docs/how-to`: никогда не переписывайте опубликованную версию или тег; корректирующий релиз — новый патч.

## Проверка релиза

```shell
uvx skillmate --version
uvx skillmate status
```

После тегирования publish-воркфлоу проверяет развёрнутый артефакт Pages и постусловия GitHub Release; `task release:check` проверяет локальное выравнивание до появления тега.

## Выведение версии

PyPI не допускает повторного использования имени выпущенного файла; опубликованные версии — история. Сломанный релиз можно пометить yank на странице проекта PyPI, чтобы его случайно не разрешали, и выпустить корректирующий патч. Причину зафиксируйте в changelog.
