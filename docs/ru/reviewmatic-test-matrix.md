# Базовый набор тестов reviewmatic

[English](../reviewmatic-test-matrix.md)

`apps/reviewmatic` — механический вспомогательный рантайм навыка `mr-review`.
TypeScript-приложение ревью, которое он заменил, удалено вместе с сокращением
рантайма; ни TypeScript-раннера тестов, ни генератора в репозитории не
осталось.

## Карта тестов

| Поверхность | Файл тестов |
| - | - |
| Поверхность команд и удалённые команды | `apps/reviewmatic/tests/test_cli_contract.py` |
| Сбор только для чтения, точные ревизии, полнота, редактирование секретов | `apps/reviewmatic/tests/test_collect.py` |
| Фон 8000 байт, приоритет задачи, раскрытые сокращения | `apps/reviewmatic/tests/test_background.py` |
| Проверка головы, позиционные и общие черновики, ответы, без публикации | `apps/reviewmatic/tests/test_drafts.py` |
| Свежесть снимка | `apps/reviewmatic/tests/test_revalidate.py` |
| Наложение глобального и локального профиля, без секретов | `apps/reviewmatic/tests/test_profiles.py` |
| Проверка версии OCR, параллельные прогоны, разбор, сравнение сессий | `apps/reviewmatic/tests/test_ocr.py` |
| Тексты навыка, словарь рантайма, карта документации, паритет хостов | `apps/reviewmatic/tests/test_skill_contract.py` |
| Авторские fixture runbook (один прогон, два прогона) | `apps/reviewmatic/tests/test_runbook_format.py` |

Материализованный переносимый контракт в `src/reviewmatic/portable/`
проверяется побайтово набором репозитория (`task generate:check`) и тестами
переносимого рантайма в `tests/test_repository.py`.

## Fixtures

- `apps/reviewmatic/tests/fixtures/ocr/` содержит JSON ревью OCR и две формы
  сравнения сессий; разборщик терпимый, а fixtures — входные данные, не
  сгенерированный вывод.
- `apps/reviewmatic/tests/golden/` содержит два авторских примера runbook. Они
  фиксируют разделы, которые навык обязан выдавать, и те, которых быть не
  должно; это не вывод рантайма, и он не перегенерируется из реализации.

## Поддельные хосты

Тесты сбора подменяют транспорт GitLab записанными ответами и проверяют
записанные вызовы; тесты черновиков запускают сгенерированный shell-блок с
поддельным `glab` в `PATH`, доказывая остановку на устаревшей голове и число
POST. Тесты пакета остаются на стандартной библиотеке.

## Слои приёмки навыка

Детерминированный слой — набор пакета выше плюс контрактные тесты
репозитория (`tests/test_skill_contracts.py`), которые читают собранный архив
`mr-review`.

Живой слой запускает пользователь: `task acceptance SKILL=mr-review` ведёт
семейство `gitlab-review-live`. Оно создаёт синтетический проект и merge
request на одноразовом локальном стенде GitLab, выписывает навык на точных
ревьюимых ревизиях, засевает ответы стартового раунда в промпт, записывает
runbook и блок черновиков, двигает голову, чтобы задействовать
`ocr session compare`, и выполняет блок черновиков (только draft notes,
никогда не публикацию), после чего удаляет фикстуру. Нужны dev-стеки, CLI
`ocr`, два настроенных алиаса ревьюеров и креды провайдера; отсутствующая
предпосылка сообщается пропуском с точной причиной. Живой прогон вне
`task check`, `check:core`, гейта Lefthook и CI.

## Зонтик приёмки

`task acceptance` (`tests/integration/acceptance.py`) ведёт живые прогоны
GitLab и Mattermost плюс минимальный поведенческий проб для каждого
непокрытого скилла. Проба устанавливает только свой скилл в изолированный
sandbox хоста, сеет маленькие fixtures и машинно проверяет артефакт;
непроверяемые скиллы пропускаются с причиной. Каждый прогон пишет
`result.json` и `summary.md` в `.build/acceptance/<timestamp>/`. Зонтик вне
гейтов; см. [how-to](how-to/skill-acceptance.md).
