# История изменений

Все заметные изменения этого проекта описаны в этом файле. Формат основан на
[Keep a Changelog](https://keepachangelog.com/ru/1.1.0/), а нумерация версий
соответствует [семантическому версионированию](https://semver.org/lang/ru/).

[English version](CHANGELOG.md)

## Не выпущено

### Изменено

- `task-prepare`, `task-review` и `task-triage` теперь используют общий механизм
  release-aware планирования: каждая принятая готовая задача привязывается к
  ближайшему совместимому milestone GitLab, а отсутствующий, несовместимый или
  устаревший planning state остаётся явным.

## \[7.0.0] - 2026-09-23

### Добавлено

- `task-triage` теперь поддерживает инкрементальный триаж одной GitLab-задачи и
  набора задач с приватными XDG-артефактами, общей оценкой `task-review`, SemVer,
  приоритетами, зависимостями и ручными командами обновления.

### Изменено

- `humanize` теперь сохраняет переданный авторский голос и подтверждённые
  утверждения, рассматривает исходный текст как недоверенный материал и отличает
  сильные признаки от сочетаний слабых паттернов письма.
- `task-prepare` теперь применяет общую оценку `task-review` к каждой задаче:
  заблокированные задачи не получают команды публикации, а неразрешённые
  уточнения сохраняют частичный статус плана.

### Исправлено

- Архивы portable distribution исключают Python bytecode и каталоги
  `__pycache__`, сохраняя воспроизводимость после тестовых запусков runner.

### Несовместимые изменения

- `task-triage` теперь принимает URL задач и наборов GitLab вместо inline-текста,
  локальных файлов и произвольных HTTPS work items. Прежний chat output с
  классами свидетельств заменён сохраняемым GitLab-анализом и вердиктами
  качества; вызывающие сценарии и triage-артефакты необходимо обновить.

## \[6.0.0] - 2026-09-22

### Добавлено

- `spec-manage` теперь поддерживает единый выбранный для проекта язык канона,
  естественный выбор режима, индексируемые расширения спецификации,
  специализированные профили требований и архитектуры, воспроизводимый аудит и
  переносимый структурный валидатор на Python 3.12+ с явными snapshot- и
  lifecycle-проверками.
- `release-prepare` теперь создает единый стабильный runbook для действий до и
  после merge, привязанный к точному составу релиза, milestone, участникам,
  reviewers, решениям по work items, неизменяемым payload и ручным командам
  `glab`.
- `stopit` получил runner на стандартной библиотеке для приватных атомарных
  handoff, привязанных к workspace и хранящихся в XDG state directory.

### Изменено

- Публикационные drafts `task-prepare` теперь используют стабильные слоты
  `plan_key`, content-addressed неизменяемые вспомогательные файлы, атомарную
  замену и блокировку в пределах слота.
- Поведенческие evals теперь могут проверять структурированные результаты
  отдельных случаев и наблюдаемые границы изменений. Hostless evaluation
  использует собранные skills и больше не выдает ожидания fixtures за
  наблюдаемое поведение модели.

### Исправлено

- Пути артефактов portable skills остаются стабильными между повторными
  запусками, а измененные payload сохраняются неизменяемо; небезопасные и
  устаревшие записи завершаются безопасным отказом.

### Несовместимые изменения

- Публикационный input `task-prepare` теперь имеет версию 2 и требует безопасный
  lowercase `plan_key`. Bundles версии 1 необходимо пересоздать, а ссылки на
  content-derived каталоги заменить на `.task-prepare/<plan_key>/`.
- `stopit` заменяет уникальные временные handoff-файлы на
  `$XDG_STATE_HOME/agent-skills/stopit/<workspace-id>/handoff.md`. Инструменты,
  сохраняющие старые временные пути, необходимо обновить.
- В release publication plans и release-записях `artifact-contracts-v2`
  появились новые обязательные bindings и решения. Существующие планы релиза
  необходимо пересоздать, а не использовать повторно.
- Существующие деревья канонических спецификаций должны объявить
  `Canonical language:` в `specs/README.md` и соответствовать новой формальной
  структуре. Смешанный язык необходимо разрешить явно до обновления документов.

## \[5.1.3] - 2026-09-21

### Исправлено

- Проверки EditorConfig теперь вызывают установленный бинарник
  `editorconfig-checker` вместо ненастроенного локального alias `ec`. Preflight
  `v5.1.2` на чистом runner остановился до создания артефактов из-за отсутствия
  этого alias.
- Релизы теперь требуют чистый pre-tag workflow для ветки `release/vX.Y.Z` до
  отправки `main` и аннотированного тега. Локальная проверка больше не требует
  ещё не опубликованный тег и не предполагает ошибочно, что release-коммит уже
  находится в `origin/main`.

## \[5.1.2] - 2026-09-21

### Исправлено

- Mise теперь использует npm installer для npm-инструментов, поэтому `npm_args`
  устанавливает закреплённые плагины Remark на чистых runners. Preflight
  `v5.1.1` остановился до создания артефактов, потому что стандартный installer
  Aube игнорировал эти аргументы плагинов.

## \[5.1.1] - 2026-09-21

### Исправлено

- GitHub Actions снова закреплены по неизменяемым SHA коммитов, как требует
  обязательная политика репозитория. Workflow `v5.1.0` был отклонён до запуска
  jobs и создания артефактов; `v5.1.1` выпускается как соответствующее
  исправление релиза.

## \[5.1.0] - 2026-09-21

### Добавлено

- Code review теперь отдельно оценивает вклад MR и накопленное влияние следующего
  релиза на SemVer, используя проверенные каталоги релизов и данные целевой ветки
  с явным fallback, когда основу релиза установить нельзя.
- Code review теперь проверяет полный список jobs для привязанного к MR pipeline
  точного head-коммита, включая ограниченные traces упавших jobs и рекурсивно
  собранные downstream pipelines.

### Изменено

- CI теперь один раз собирает переносимые навыки и передаёт неизменяемый артефакт
  прямым задачам Task вместо запуска проверок через агрегаторы `ci:*`.
- Метаданные пакета теперь закрепляют skills installer `1.7.0`, а проверка
  совместимости охватывает настроенный toolchain OpenCode `1.18.31`.
- Проверки качества репозитория теперь используют закреплённый Mise toolchain,
  строгие проверки типов и lint для Python, точечные pre-commit hooks и единый
  документированный gate `task pre-push`. Пользователям переносимых навыков и
  пакета OpenCode миграция не требуется.

### Исправлено

- Code review теперь привязывает данные pipeline к merge request, использует
  проверенный снимок целевой ветки MR, если текущий target-коммит недоступен
  локально, и скрывает authorization headers, облачные credentials, URL с
  credentials, JSON secrets и приватные ключи в traces упавших jobs.

### Удалено

- Удалены машинная трассируемость спецификаций, трейлеры влияния коммитов, хуки и
  соответствующие проверки CI. Источником истины остаются канонические
  Markdown-спецификации и семантические процессы `spec-manage`.

## \[5.0.0] - 2026-09-18

### Добавлено

- Подготовка MR теперь создаёт стабильные двуязычные планы публикации, шаблоны
  проекта, ручные команды `glab` и привязанные к доказательствам проверки
  актуальности.

### Исправлено

- Уточнены случаи применения askme и порядок ручного продолжения. Проверка npm
  релиза теперь учитывает задержку распространения пакета в реестре.

### Критические изменения

- Подготовка MR требует черновики, привязанные к локали, и исчерпывающую оценку
  лейблов. Пересоздайте устаревшие черновики и планы публикации.

## \[4.1.1] - 2026-09-17

### Исправлено

- Отчёт code-review показывает версию, подставленную при сборке, компактное
  оформление MR, единственный список изменений лейблов с командой и понятные
  подписи действий. Убраны внутренние поля и повторные копии patch.
- Закрытые треды с проверенным объяснением или применённым suggestion больше
  не требуют повторного ответа. Инструкции используют humanize и предпочитают
  групповые лейблы семантически равнозначным обычным.
- Для локальных исправлений сохранён готовый к копированию patch. Добавлены
  регрессии на вид отчёта, замену лейблов и воспроизводимую подстановку версии.

## \[4.1.0] - 2026-09-17

### Добавлено

- Проверка кода теперь при каждом запуске разбирает все открытые и закрытые
  дискуссии, включая неизменённые MR. Планы contract-5 привязывают решения к
  полной хронологии треда, сохраняют явный `unchanged` и проверяют необязательную
  атрибуцию исправляющего коммита без вывода SHA.

### Изменено

- Для принятой проблемы в треде теперь обязательны валидный suggestion или
  patch, согласованный переход resolve/reopen и отдельные команды комментария и
  изменения состояния. Неякорные исправления публикуются как готовый к запуску
  heredoc с `git apply`.

## \[4.0.0] - 2026-09-17

### Изменено

- Обычные bounded-изменения файлов проекта теперь записываются напрямую с
  атомарной заменой. Предпросмотр и подтверждение остаются только для внешних
  публикаций, пользовательской конфигурации, разрушительной очистки, изменений
  истории, релизов и жизненного цикла пакетов.
- Проверка кода теперь готовит прямые ручные команды `glab` и body-файлы. GitLab
  discussions, notes и issues текущего пользователя остаются источником фактов
  для инкрементальной оценки публикаций.

### Удалено

- Удалены helper `review_publish.py`, подтверждение action digest, receipts,
  скрытые publication markers, retry state и postcondition verification.
- Удалены confirmation-based project-write flows, включая
  `ast-grep rewrite --apply` и прежние фазы apply для work-item/team artifacts.

## \[3.2.1] - 2026-09-16

### Исправлено

- Проверка кода отклоняет структурно одинаковые принятые замечания до создания
  или применения плана публикации: независимый критик больше не создаёт второй
  комментарий об одной проблеме.
- Помощник публикации GitLab отправляет JSON-запросы с явным `Content-Type`,
  поэтому подтверждённые line discussions принимаются GitLab.

## \[3.2.0] - 2026-09-16

### Добавлено

- Проверка кода получила возобновляемый автомат состояний под управлением runner
  с командами `status`, `next`, шаблонами для критика, решения и содержимого, а
  также финальным ответом только из актуального плана публикации контракта 4.

### Изменено

- `skills-opencode reconcile` больше не проверяет и не удаляет переносимые навыки
  или их lock-файлы. Удалённые в источнике навыки обрабатывают `skills update/remove`.
- Документация жизненного цикла переносимых навыков теперь направляет установку,
  обновление, просмотр и удаление через официальный CLI навыков.

### Безопасность

- Проверка кода блокирует результат при неполных, нарушающих порядок или
  устаревших привязках доказательств, критика, решения, плана, Markdown и базового
  состояния. Активация ревью и подтверждённая публикация используют общую
  блокировку, поэтому вытесненный план нельзя показать или выполнить.

## \[3.1.1] - 2026-09-16

### Выпуск

- Артефакты исправлений и диагностика проверки кода из 3.1.0 повторно публикуются
  под новым неизменяемым тегом, поскольку npm зарегистрировал 3.1.0 без доступного
  для загрузки tar-архива.
- Среда выполнения, схемы, документация и совместимость не изменились по сравнению
  с 3.1.0; проверка релиза теперь учитывает ограниченную задержку распространения
  данных в реестре.

## \[3.1.0] - 2026-09-16

### Добавлено

- Проверка кода готовит один проверенный артефакт исправления для каждого
  актуального замечания, исправления в обсуждении и локального исправления автора:
  точный GitLab `suggestion`, когда это допускает позиция в diff, или адресуемый
  по содержимому унифицированный патч в остальных случаях.
- План публикации показывает режим исправления, операцию, позицию, контрольную
  сумму SHA-256 патча, полный diff и команды ручного применения
  `git apply --check` и `git apply`.

### Изменено

- Помощник публикации выводит ограниченную и очищенную диагностику запросов и
  отличает однозначный отказ GitLab от неопределённого результата изменения.
- Структурированные планы контракта версии 2 остаются исполняемыми, а старые
  базовые планы переходят к полному ревью перед созданием артефактов исправлений
  контракта версии 3.

## \[3.0.0] - 2026-09-16

### Добавлено

- Проверка кода может подготовить привязанные к контрольным суммам комментарии
  GitLab, ответы в обсуждениях, предложения задач и изменения меток. Каждое
  действие подтверждается отдельно, повторно проверяет состояние GitLab и
  записывает локальную квитанцию с возможностью продолжения.
- `skills-opencode reconcile` архивирует устаревшие компоненты с подтверждённой
  принадлежностью перед очисткой, сохраняет пользовательские и изменённые файлы и
  откатывает запланированные пути при ошибке подтверждённой операции.

### Изменено

- Административные операции OpenCode выполняются только через CLI. Команды
  `skills-opencode capabilities`, `doctor`, `reconcile`, `agent` и `critic`
  сохраняют детерминированные интерфейсы, а основной плагин предоставляет только
  инструмент `route` с маршрутными квитанциями.
- Поддерживаемый публичный состав включает 27 переносимых навыков, 27 одноимённых
  команд навыков, 6 агентов, 3 необязательных плагина и 1 инструмент пакета.

### Удалено

- Универсальные навык и команда `doit` удалены; обычная инженерная работа теперь
  напрямую следует инструкциям активной среды и репозитория.
- Переносимые навык и команда `lsp-report` удалены; для отчёта LSP в OpenCode
  используйте `skills-opencode doctor`.
- Адаптеры команд `/agent-profiles`, `/capabilities`, `/doctor` и `/reconcile`, а
  также соответствующие инструменты пакета удалены.

### Миграция

- Обновите пакет, затем запустите `skills-opencode reconcile --dry-run` и точную
  команду подтверждения из результата, чтобы архивировать и удалить неизменённые
  устаревшие компоненты пакета.
- Удалите установленные копии `doit` и `lsp-report` через `skills remove` или
  разрешите подтверждённой сверке пакета удалить копии с маркером источника Pages.

## \[2.4.1] - 2026-09-16

### Исправлено

- Публичная документация теперь представлена структурно согласованными английскими
  и русскими версиями с естественными переводами и отдельными файлами истории

- Проверка локалей теперь обнаруживает различия в структуре блоков Markdown, а

## \[2.4.0] - 2026-09-16

### Добавлено

- Проверка кода вновь поддерживает поэтапный процесс с сохранением подтверждающих

- Управление спецификацией сохраняет историю решений и обеспечивает явную

## \[2.3.1] - 2026-09-15

### Исправлено

## \[2.3.0] - 2026-09-15

### Добавлено

- Структурированная корневая и контекстная справка CLI теперь описывает каждую
  команду и группу, допустимые параметры, безопасный порядок изменений, работу
  с областями и примеры.
- Единые списки выбора в терминале содержат понятные подсказки по клавишам и
  позволяют при установке выбирать сразу несколько произвольных команд, агентов
  и плагинов.
- Документация по Diataxis теперь содержит специализированные учебные руководства,
  практические инструкции, справочные материалы и объяснения для переносимых
  навыков и интеграции с OpenCode.

### Изменено

- Пользовательская документация теперь ссылается на стабильные каналы npm, а
  генерируемые команды подтверждения для OpenCode сохраняют точные версии пакетов;
  глобальный запуск CLI не зависит от текущего каталога.
