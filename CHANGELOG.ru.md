# История изменений

Все заметные изменения этого проекта описаны в этом файле. Формат основан на
[Keep a Changelog](https://keepachangelog.com/ru/1.1.0/), а нумерация версий
соответствует [семантическому версионированию](https://semver.org/lang/ru/).

[English version](CHANGELOG.md)

## [3.0.0] - 2026-09-16

### Добавлено

- Проверка кода может подготовить привязанные к контрольным суммам комментарии
  GitLab, ответы в обсуждениях, предложения задач и изменения меток. Каждое
  действие подтверждается отдельно, повторно проверяет состояние GitLab и
  записывает локальную квитанцию с возможностью продолжения.
- `skills-opencode reconcile` архивирует устаревшие компоненты с подтверждённой
  принадлежностью перед очисткой, сохраняет пользовательские и изменённые файлы и
  откатывает запланированные пути при ошибке подтверждённой операции.

### Изменено

- Административные операции OpenCode выполняются только через CLI. Команды
  `skills-opencode capabilities`, `doctor`, `reconcile`, `agent` и `critic`
  сохраняют детерминированные интерфейсы, а основной плагин предоставляет только
  инструмент `route` с маршрутными квитанциями.
- Поддерживаемый публичный состав включает 27 переносимых навыков, 27 одноимённых
  команд навыков, 6 агентов, 3 необязательных плагина и 1 инструмент пакета.

### Удалено

- Универсальные навык и команда `doit` удалены; обычная инженерная работа теперь
  напрямую следует инструкциям активной среды и репозитория.
- Переносимые навык и команда `lsp-report` удалены; для отчёта LSP в OpenCode
  используйте `skills-opencode doctor`.
- Адаптеры команд `/agent-profiles`, `/capabilities`, `/doctor` и `/reconcile`, а
  также соответствующие инструменты пакета удалены.

### Миграция

- Обновите пакет, затем запустите `skills-opencode reconcile --dry-run` и точную
  команду подтверждения из результата, чтобы архивировать и удалить неизменённые
  устаревшие компоненты пакета.
- Удалите установленные копии `doit` и `lsp-report` через `skills remove` или
  разрешите подтверждённой сверке пакета удалить копии с маркером источника Pages.

- Структурированная корневая и контекстная справка CLI теперь описывает каждую

- Единые списки выбора в терминале содержат понятные подсказки по клавишам и
  позволяют при установке выбирать сразу несколько произвольных команд, агентов
  и плагинов.
- Документация по Diataxis теперь содержит специализированные учебные руководства,
  практические инструкции, справочные материалы и объяснения для переносимых
  навыков и интеграции с OpenCode.

### Изменено

- Пользовательская документация теперь ссылается на стабильные каналы npm, а
  генерируемые команды подтверждения для OpenCode сохраняют точные версии пакетов;
  глобальный запуск CLI не зависит от текущего каталога.
- Для версий проекта, переносимого установщика и совместимости с OpenCode теперь
  используются единые проверяемые источники; сведения о версии в метаданных
  каждого навыка удалены в пользу метаданных дистрибутива и дайджестов архивов с
  адресацией по содержимому.

## [2.2.3] - 2026-09-15

### Исправлено

- Результат проверки кода теперь содержит абсолютные пути к артефактам в простом

  служат только для предварительного просмотра и никогда не изменяют GitLab
  автоматически.

## [2.2.2] - 2026-09-14

### Исправлено

- Проверка npm после публикации теперь повторяет запросы к конечной точке
  `attestations`, пока в реестре распространяются сведения о происхождении, и не

## [2.2.1] - 2026-09-14

### Добавлено

- Добавлены корневые инструкции для агентов, шаблоны назначения ответственных за
  запросы на включение изменений и их проверки, исчерпывающая проверка JSON Schema на конкретных
  экземплярах и аудит зафиксированных зависимостей.
- Добавлены точные межканальные манифесты выпуска, проверки работоспособности
  реестра npm, проверка подписей и происхождения по SLSA, а также автоматическое
  создание GitHub Release.

### Изменено

- CI теперь запускает независимые проверки спецификации, статического анализа,
  Python, переносимого дистрибутива, оценок, пакета и поиска секретов, объединённые
  одной стабильной итоговой проверкой.
- Единый процесс для тега выполняет полную предварительную проверку перед
  публикацией точных артефактов Pages и npm, а затем проверяет оба канала.
- Строгая проверка типов и форматирование Python теперь охватывают поддерживаемые
  обработчики внутри навыков и все ранее исключённые поддерживаемые исходные файлы.

### Исправлено

- Стандартное обнаружение тестов pytest теперь включает 41 локальный
  регрессионный тест Mattermost, а проверки pre-commit обрабатывают удаления,
  схемы, спецификации и файлы инструментов.
- Обычная проверка CI при отправке изменений больше не запускается для тегов
  выпуска, что устраняет прежний сбой при вычислении диапазона влияния на
  спецификацию при обработке тегов.

## [2.2.0] - 2026-09-14

### Добавлено

- CI для тегов выпуска теперь разворачивает переносимый дистрибутив в GitHub
  Pages и проверяет опубликованные метаданные выпуска, пути к архивам и дайджесты
  SHA-256.
- Содержимое Pages предоставляет индекс обнаружения `0.2.0` для agentskills.io и
  по одному детерминированному архиву с адресацией по содержимому для каждого
  общедоступного навыка.

### Изменено

- Для переносимой установки теперь используется обновляемый стабильный источник
  `https://kisev.github.io/skills` вместо селекторов репозитория Git.
- Исходные точки входа называются `SKILL.source.md`; общие контракты и среды
  выполнения внедряются только в игнорируемый результат сборки `.build/skills`,
  благодаря чему из дерева исходного кода удалены 126 зафиксированных в Git
  сгенерированных копий.
- `@kisev/skills-opencode@2.2.0`, метаданные переносимого дистрибутива, тег выпуска
  и GitHub Release согласованы по версиям и привязаны к одному коммиту, но
  сохраняют независимые жизненные циклы установки и обновления.

### Миграция

- Существующие переносимые установки из Git остаются привязанными к прежнему
  источнику. Повторите `skills add` с `https://kisev.github.io/skills`, указав ту
  же область и тех же агентов, чтобы перепривязать установки до использования
  `skills update`.

## [2.1.0] - 2026-09-14

### Добавлено

- Командные процессы теперь поддерживают профили с жёсткими требованиями к
  конфиденциальности, автоматический выбор профиля по умолчанию, пошаговую
  самостоятельную настройку по явно указанным файлам, URL, репозиториям или
  подтверждающим данным коннекторов, а также обновление профилей вне
  общедоступного репозитория с привязкой к дайджесту.
- `team-retro` и `team-roadmap` содержат полные процессы сбора подтверждающих
  материалов и сборщик данных GitLab за ограниченный период со строгой семантикой
  `[since, until)`, постраничной загрузкой, устранением дубликатов, сведениями о
  происхождении временных меток и явным обозначением частичных результатов.
- `slides-prompts-prepare` сочетает выбранную пользователем тему с краткими
  фактическими сведениями о команде, проекте, технологиях и поставке, сохраняя по
  одному промпту на слайд и уже существующие изображения.
- Чтение Mattermost теперь включает кэширование SQLite с изоляцией по источнику и
  пользователю, повторную проверку доступа в пределах точно заданной области, сбор реакций и
  сведений об участниках, ограниченные периоды и очистку кэша с подтверждением.
- Процессы подготовки в GitLab могут на основе актуального каталога формировать
  рекомендации по выбору меток с учётом их смысла, не заменяя несвязанные метки.
- Проверка кода и подготовка выпуска учитывают роли при сборе подтверждающих
  материалов, проверяют архитектуру и состав выпуска и дают рекомендации по
  сопутствующим артефактам.

### Изменено

- `agents-md`, `commit-msg` и `humanize` используют более строгие границы
  доказательной базы и более явные контракты выходных данных.
- Файлы командных профилей требуют закрытых прав доступа в файловой системе, а их
  необработанное содержимое никогда не включается в планы предварительного
  просмотра или отчёты.
- Версии метаданных Mattermost и пяти общих командных процессов в переносимом
  дистрибутиве теперь равны `2.1.0`; пакет OpenCode, тег выпуска и
  документация используют ту же версию.

### Исправлено

- Тестовые данные для оценки Mattermost теперь соответствуют действующим
  контрактам запросов только методом `GET` и передачи cookie через стандартный ввод.
- Проверки pre-commit изолируют своё окружение Git, а форматирование оценок и схем
  GitLab остаётся детерминированным.

## [2.0.6] - 2026-09-11

### Исправлено

- Авторизация в доверенном режиме Goal Mode теперь охватывает каждое действие, явно

## [2.0.3] - 2026-09-11

### Исправлено

- Мастер установки теперь явно различает адаптеры команд навыков и пакета и
  объясняет, что переносимые навыки устанавливаются отдельно.
- Человекочитаемый предварительный просмотр `reconcile` блокируется при изменённых
  управляемых ресурсах или конфликтах владения, перечисляет все блокирующие пути и
  показывает способ исправления вместо `Apply`.
- Новый пробный запуск в одной области отменяет прежний неиспользованный
  предварительный просмотр для операций установщика, `reconcile`, агента и критика;
  дайджесты плана и подтверждения разделены, а подтверждение для отменённого
  предварительного просмотра отклоняется.
- Заблокированный `reconcile` не создаёт новую квитанцию и не раскрывает данные для
  подтверждения.
- Теперь в документации описаны постоянная установка пакета через npm,
  подтверждение в установщике, активация плагина и перезапуск перед `reconcile`.

### Без изменений

- Версия метаданных переносимых навыков остаётся `2.0.0`; реестр, среда выполнения,
  агенты, плагины и схема манифеста не изменились.

## [2.0.2] - 2026-09-10

### Исправлено

### Без изменений

  изменились.

## [2.0.1] - 2026-09-10

### Исправлено

- Проверка CI для влияния на спецификацию теперь детерминированно определяет
  диапазоны для запросов на включение изменений, обычной отправки изменений в ветку, первой отправки
  в новую ветку и отправки тегов.
- При отправке тега в Git больше не передаётся нулевой SHA: проверка подтверждает,
  что коммит выпуска достижим из `origin/main`, а затем строит диапазон влияния от
  его первого родителя.
- При некорректных, отсутствующих или недостижимых SHA события проверка завершается
  безопасным отказом.

### Без изменений

- Это исправление затрагивает только CI: среда выполнения, навыки, общедоступный
  реестр и поведенческие контракты не изменились. Версия метаданных переносимых
  навыков остаётся `2.0.0`.

## [2.0.0] - 2026-09-10

### Несовместимые изменения

- Навыки `attempt`, `schedule`, `usage` и `overview` удалены без замены.
- `project-spec`, `skill-improver` и `walkthrough` переименованы в `spec-manage`,
  `skill-improve` и `code-explain` соответственно.
- `team-workflow` заменён пятью фиксированными навыками: `team-sprint-start`,
  `team-sprint-close`, `team-retro`, `team-roadmap` и `slides-prompts-prepare`.
- Устаревшие интерфейсы навыков, команд и плагинов удалены, включая слеш-команду
  `/route`; инструмент пакета `route` остаётся доступен без слеш-команды.
- Псевдонимы действий и режимов удалены: в общедоступном интерфейсе используются
  только точные имена из каталога.

### Установка и миграция

- Переносимые навыки устанавливаются напрямую из тега GitHub с зафиксированной
  версией исполняемого инструмента (для Codex замените `opencode` на `codex`):

  ```shell
  npx --yes skills@1.5.23 add https://github.com/kisev/skills/tree/v2.0.0 \
    --agent opencode --skill '*' --copy --yes
  ```

- Точная миграция с `v1.2.0` использует реестр миграции и сохраняет сведения о
  владении и контрольных суммах; переименованные навыки требуют ручной проверки
  нового имени.
- `reconcile` переносит выведенные из эксплуатации ресурсы с точно подтверждённым
  владением в закрытый архив с адресацией по содержимому и статусом
  `archive-pending`; изменённые, принадлежащие пользователю и неизвестные ресурсы
  остаются конфликтами. Архивация, восстановление и очистка в этот выпуск не входят.

### OpenCode

- `@kisev/skills-opencode@2.0.0` совместим с OpenCode `>=1.18.29 <1.19.0` и
  требует Node.js 22+.
- Переносимые навыки и необязательная интеграция с OpenCode устанавливаются
  независимо; интеграция не включает навыки и не изменяет `opencode.json`.

### Известные ограничения

- Mattermost ещё не полностью соответствует заявленным сценариям.
- Состояние среды выполнения и `doctor` требуют дальнейшего усиления защиты.
- Плагины с состоянием по-прежнему включаются только явно; планировщик и связанные
  обёртки по умолчанию отключены; для `ast-grep` и `rtk` необходимо заранее
  установить соответствующие CLI.
- Оценки на реальных моделях не входят в обычную проверку качества и запускаются
  только явно в доверенной среде.

## [1.1.0] - 2026-09-06

### Добавлено

- Добавлен прямой CLI для просмотра реестра, настройки моделей и вариантов
  фиксированных агентов, явного `reconcile` и безопасного добавления или удаления
  дополнительных критиков.
- Добавлены инструмент пакета `agent_profiles` и четыре необязательные простые
  слеш-команды без отдельного навыка.
- Добавлены отдельная конфигурация профилей и семантический манифест развёртывания
  с точным набором критиков, хешами сгенерированных файлов и сохранением настроек
  при обновлении пакета.

### Изменено

- Полные контракты менеджера, критика и проверки теперь требуют актуальной карточки
  и актуального одобрения, запрещают исполнителю напрямую вносить исправления и используют
  точные списки разрешений без префиксных шаблонов.
- Владение фиксированными агентами перенесено из общего установщика в область
  профилей; команды и плагины по-прежнему принадлежат общему установщику.
- Все изменения установщика и профилей используют закрытые квитанции с TTL,
  блокировку жизненного цикла, итоговую проверку реестра и журналируемую транзакцию
  по принципу "всё или откат" с восстановлением.

### Безопасность

- Совпадение точного имени с ресурсом пользователя блокирует применение,
  неизвестные агенты не изменяются, а миграция `1.0.0` требует точного манифеста и
  совпадения SHA-256.
- Примитивы состояния не допускают символьные ссылки в качестве целевых и
  родительских путей, используют закрытые права доступа и атомарную запись, а
  также безопасно дописывают данные.
