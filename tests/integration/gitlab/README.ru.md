# Локальные тесты GitLab workflows

[English](README.md)

Тесты используют общее [dev-окружение](../../../dev/README.ru.md):
GitLab CE `18.11.11-ce.0`, GitLab Runner `v18.11.0`
и закреплённый в репозитории `glab 1.120.0`. Shell jobs выполняются в отдельном
контейнере Runner без Docker socket хоста. Docker executor и платные функции EE
не входят в охват. Обычный `task check` не требует работающего сервера.

## Запуск

Нужны Linux, Docker Engine, Compose v2, OpenSSL, Git, инструменты Mise и рабочий
Chromium. Старт GitLab занимает несколько минут; памяти должно хватать для
сервера и браузера. Образы и браузер
нужно подготовить заранее. При их отсутствии preflight сохраняет диагностику и
останавливается, не подменяя версии.

```sh
mise install
mise exec -- agent-browser install
task generate
task env:gitlab:up
task test:integration:gitlab:preflight
task test:integration:gitlab
```

Повтори `task test:integration:gitlab` на уже работающем сервисе. Тесты не управляют
контейнерами и не создают аккаунты: подготовку выполняет `env:gitlab:up`.
По умолчанию используется `docker-compose`; для CLI-плагина добавь
`COMPOSE="docker compose"`. `GL_TEST_PORT` задаёт localhost HTTPS-порт
(по умолчанию `443`); сохраняй его для последующих команд. Проект Compose один,
`skills-dev`. Версии образов нельзя переопределить.
Для полных workflows используй стандартный порт: `glab 1.120.0` отвергает порт
в `--hostname`. Нестандартные порты подходят только для API/lifecycle.
`env:gitlab:up` печатает URL группы manual; управление и очистка описаны
в гайде dev-окружения. При отсутствии готовности или fixtures тест сообщает,
что нужно выполнить `up`, а не запускает сервис неявно.

HTTPS опубликован только на `127.0.0.1`. В URL используй `localhost`: это имя
сертификата отдельного CA стенда. Тесты проверяют CA; отдельная сессия Chromium
доверяет только проверенному ключу сертификата. Системное доверие не меняется.
GitLab и Runner общаются по внутренней Compose-сети. Записи затрагивают только
синтетические тестовые репозитории. Инициализация создаёт группы с именами
`fixtures` и `manual` и уникальными путями стенда. Группой `manual` владеет отдельный
аккаунт; его credentials доступны только при инициализации, не как actor автоматики.
Обычные прогоны не читают, не обходят, не хешируют, не изменяют и не очищают её
содержимое и локальные личные каталоги. Driver отклоняет каталоги проектов и
запросы вне fixtures до обращения к серверу. Старые данные `free` остаются на месте,
без fingerprint-сверки и миграции.
Не помещай в стенд производственные данные.
Для личного входа используй `users.manual` из приватного `state/fixtures.json`;
создавай проекты в напечатанной группе manual. Не передавай этот файл другим.

## Доказательства и ограничения

Приватные credentials и изолированные Git/glab/XDG находятся в игнорируемом
`.build/gitlab-test/gitlab-workflows/state/`. Отчёты хранятся отдельно:
`reports/<run>/result.json`; `reports/latest.json` указывает на последнюю
операцию. Сохраняются ошибки, версии, время прогона, замеры ресурсов контейнеров,
ответы API, traces и screenshots. Ошибки и таймауты дают ненулевой exit code.
Подготовка проверяется отдельно от разрешённых синтетических записей.
`browser-network.json` сохраняет URL, методы, статусы и transport errors запросов
XHR/fetch, в том числе при сбое UI-проверки. Headers, cookies и bodies не сохраняются.
`preflight.json` содержит версии Engine/Compose, identities закреплённых образов,
версии CLI/браузера, SHA и dirty state checkout и ресурсы хоста.
`automation-access.json` содержит ограниченные запросы driver, не данные manual.
Браузер использует отдельные XDG-каталоги и короткий приватный временный каталог
сокетов. Healthcheck ждёт завершения startup post-reconfigure hook, затем обращается
напрямую к Puma и проверяет все зависимости. Маркер завершения хранится в tmpfs
контейнера, очищается перед reconfigure и не переживает рестарт контейнера.
Это исключает запуск fixture-проверок во время отложенного рестарта Workhorse
в Omnibus, даже если Puma и страница входа уже отвечают успешно. Ошибки запуска
остаются ошибками; записи API не повторяются.

| Сценарий | Ожидаемый результат | Проверка состояния сервера |
| - | - | - |
| Аккаунты и повтор | Собственные аккаунты переиспользуются | ID авторизованных пользователей и проектов |
| Пагинация | Настоящий glab проходит несколько страниц | Все три issues прогона при `per_page=1` |
| Каталог helpers и роли | Настоящие collectors MR/релиза работают от автора и ревьюера; reviewmatic и triage читают повторно используемый каталог из 101 label | Все fixture labels присутствуют; collectors MR/релиза подтверждают минимум две страницы |
| Метаданные и связи | CE принимает labels, milestones, `relates_to` | GET issues и links возвращает точные значения |
| Tags/releases | Релиз привязан к fixture commit | GET release возвращает точный SHA |
| Shell CI | Выполняются success, allowed failure и child job | Состояния pipeline/jobs и маркеры настоящих traces на точном SHA |
| Inline | Приняты old/new/context-позиции | Возвращённые position и head SHA совпадают с запросом |
| Suggestions | Сервер распознаёт suggestion | Непустые серверные метаданные; браузер проверяет файл после применения |
| Ответы и треды | Ответ автора, отдельные resolve/reopen | ID автора и resolved читаются после каждого действия |
| Негативный API | Outsider и неверная строка отвергнуты | Ожидаемый non-2xx, без успешной записи |
| Подготовка MR/релиза | Полный evidence точного head без публикации | Discussions не изменились; неполный evidence helper отклоняется |
| Публикация MR | Копируемые команды от ревьюера и автора | Точные title/description/labels, включая спецсимволы; пользовательские notes не изменились |
| Публикация task | Копируемая GraphQL-команда с marker wrapper | Title, labels и milestone настоящего issue совпадают с планом |
| Task prepare/triage | Локальный план и настоящая коллекция | Каталог issues не изменился при подготовке |
| Reviewmatic | Подготовка, presentation repair, затем копируемые команды | Находки, suggestions и fixture receipts сохранены; grouped suggestions и ответы опубликованы |
| CI-only refresh | Повтор настоящего shell CI на прежнем SHA, затем финализация того же черновика | Дополнительный CI snapshot; исходные находки/evidence/receipts сохранены; повторного `startReview` нет |
| Material refresh | Сбор изменившихся discussions без публикации и подмены receipts | Находки/dispositions и исходный черновик сохранены; новые receipts пусты; предыдущий план доступен |
| TUI | Настоящий Ink CLI в PTY; отмена подтверждения, затем ответ | Нет ранней записи; ровно один ответ ревьюера; статус треда прежний; transcript сохранён |
| Браузер | Single и cross-file grouped suggestions применяются | Screenshots, точные файлы и флаги применения; частичное применение не считается полным исправлением |
| Transport fault/retry | Синтетический отказ CLI, затем настоящий collector | Ошибка даёт nonzero; повтор собирает полный evidence; сервер не изменился |
| Mutation faults | Отмена до отправки; отмена/таймаут после настоящей записи с подавленным ответом | Nonzero job; ровно один точный issue после контролируемого повтора или read-only сверки; неоднозначную запись вслепую не повторяют |
| Публикация task triage | Настоящий helper собирает и формирует план, команды копируются от автора/ревьюера | Подготовка не пишет; точные title/description/labels/milestone и поддерживаемая CE связь |
| Workflows релиза | Точный inventory содержит merged component, ревьюера и closing issue; readiness привязана к evidence; команды pre/post-merge копируются | Полный inventory, точные тексты MR/release и publication SHA; fixture-решения не выдают за оценку модели |
| Граница сохранения (отдельная lifecycle-задача) | Down/up и recreate сохраняют fixtures | Деревья branches/tags, discussions issues/MR и метаданные fixtures совпадают; сверка содержимого manual не заявляется |

Harness **не доказывает** полную матрицу приёмки. Ещё не проверены полная
пагинация всех ресурсов helpers и роли всех шести workflows, команды reviewmatic для
old/new/context и single suggestion, issues и отдельные действия над статусом
треда в TUI, восстановление stale grouped suggestions
в одном файле, цикл информационных запросов и stale analysis в task triage,
полный негативный/ролевой охват релиза и отмена/повтор mutation в TUI во время
выполнения. Retention-проверки ограничены fixtures: payloads manual не читаются,
сверка их содержимого не заявляется. Детерминированные fixture receipts не являются
настоящими запусками critic. Базовые API-проверки и offline
тесты не заменяют эти доказательства.
Пока обязательный охват неполон, `test` перечисляет недостающие случаи и
возвращает ненулевой exit code, даже если все доступные базовые сценарии прошли.
Отчёт содержит UTC `started_at`, pass/fail/not-run и время каждого сценария,
а также начальные и итоговые замеры ресурсов. Обычные тесты не выполняют down/up;
`task test:integration:lifecycle` отдельно проверяет сохранность в этом же dev-окружении.
Синтетический transport wrapper явно помечен как
fault injection и не считается доказательством сетевого ответа GitLab.
`browser-remap-<sha>.json` сохраняет настоящий UI serializer до навигации.
MR diff refs могут обновиться, пока оставшийся discussion ещё неактивен и привязан
к старой позиции. Браузер ждёт активную позицию на точном head, затем один раз
открывает diff и ждёт нужный discussion, без повторных загрузок и mutation retries.
Driver TUI ждёт полный synchronized frame и footer действий detail-view, а не
заголовок note, который есть и в overview.
Команда release announcement сохраняет attachment промпта без несовместимого
флага `--unique`. При потерянном ответе перед повтором проверяют настоящий discussion;
advisory marker не доказывает запись и не защищает от дубликата.

## Очистка

`task env:gitlab:clean` сразу удаляет данные GitLab, включая manual и приватные
credentials, без подтверждения. Отчёты сохраняются. Для пересоздания контейнеров
без удаления данных используй `task env:gitlab:recreate`. Обычные тесты не очищают
данные; безопасность очистки проверяется offline, без другого disposable-сервера.

## Опциональный live

```sh
EVAL_HOST=opencode EVAL_MODEL=provider/model EVAL_TIMEOUT=300 \
  EVAL_MAX_TOKENS=12000 EVAL_MAX_COST=1 task test:integration:gitlab:live
```

Задай реальные значения и явно передай credentials/конфигурацию провайдера.
Используются существующие адаптеры `opencode`/`codex`; глобальные credentials
не копируются. Проверяются MR-preparation artifact и ручная граница публикации,
а не только слова агента. Это не live-оценка всех шести workflows. Live использует
собственные fixture/отчёт и не запускает повторно детерминированную матрицу. Отсутствие
настроек, credentials или telemetry токенов/стоимости даёт ошибку. Таймаут
ограничивает выполнение; бюджет проверяется по telemetry после запуска, а не
как предоплаченный лимит расходов. Live опционален и не требует CI job.

При ошибке сохрани состояние, прочитай отчёт и `task env:gitlab:logs`, исправь
причину и повтори. Не сбрасывай постоянные данные ради зелёного теста.
