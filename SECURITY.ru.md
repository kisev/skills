# Политика безопасности

[English](SECURITY.md)

## Сообщение об уязвимости

Не публикуйте сведения о возможной уязвимости, учетные данные или пример
эксплуатации в Issues, Discussions или запросе на включение изменений. Создайте
закрытое уведомление об уязвимости на вкладке Security репозитория и укажите
затронутую версию, условия воспроизведения, ожидаемое и фактическое поведение, а
также возможные последствия. Если GitHub не поддерживает закрытую отправку таких
сообщений, не раскрывайте подробности публично. Сначала запросите у
сопровождающего закрытый канал через профиль владельца репозитория.

Не включайте в сообщение действующие токены, пароли, коды MFA, персональные
данные или данные систем из рабочей среды. Используйте отозванные или
синтетические значения.

## Границы проекта

- Ресурсы переносимого навыка не должны зависеть от файлов за пределами корня
  установленного навыка.
- Исполняемые модули на Python используют только стандартную библиотеку и не
  устанавливают зависимости.
- Внешние публикации, пользовательская конфигурация, разрушительные операции,
  изменения истории, релизы и жизненный цикл пакетов требуют предварительного
  просмотра и подтверждения; установщик OpenCode требует интерактивного согласия
  или явного `--yes`; применение config связывает предпросмотр в том же процессе
  с исходными байтами и одноразовым подтверждением с ограниченным сроком действия.
- Проверка кода готовит защищённые ручные команды helper публикации. Отдельный
  helper хранит резервирование, проверенные квитанции и состояние восстановления;
  неопределённый результат блокирует повтор до проверки. GitLab остаётся удалённым источником фактов.
- Подтверждённая установка с выбранным core добавляет плагин в `opencode.json`
  и может установить npm-зависимости. Хуков жизненного цикла npm нет; посторонние
  пользовательские записи и изменённые файлы сохраняются.
- По умолчанию выбрана только обёртка `rtk`. Настройки внешней
  аутентификации остаются под управлением пользователя и не должны передаваться
  через запрос к модели, `argv` или журналы.

## Поддерживаемые версии

Поддерживаются последние опубликованные стабильные версии переносимых навыков и
npm-пакета. Стабильный индекс GitHub Pages обновляется только при появлении нового
тега выпуска и связывает каждый адресуемый по содержимому архив с контрольной
суммой SHA-256; при несовпадении установка прерывается. Исправления безопасности
публикуются в новой патч-версии; существующие теги и содержимое опубликованных
архивов не переписываются.
