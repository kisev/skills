# Сообщение commit

## Алгоритм

1. Убедись, что текущая директория находится внутри Git worktree. Если нет,
   сообщи об этом.
2. Получи `git status --short`, `git diff --cached --stat` и `git diff --cached`.
3. Если есть staged changes, формируй сообщение только по ним. Unstaged и
   untracked изменения в этот commit не войдут.
4. Если staged changes нет, проанализируй tracked diff и untracked files как
   предполагаемый набор будущего commit. Содержимое untracked файлов читай
   выборочно; не открывай большие, двоичные файлы и возможные секреты без причины.
5. Если пользователь явно задал набор путей или попросил совместно рассмотреть
   staged и unstaged изменения, используй только эту область.
6. Определи единый результат и пользовательский либо технический эффект.
7. Выведи ровно одну строку либо `no changes to commit`.

## Правила

- Используй Conventional Commit: `type[optional scope][!]: description`.
- Выбирай `type` по фактическому эффекту; не выдумывай scope, если он не помогает.
- Не добавляй имена файлов, пути, идентификаторы задач и пустые слова вроде
  `changes`.
- Не объединяй несвязанные изменения вымышленной общей формулировкой. Если единое
  сообщение невозможно, выбери наиболее значимый staged effect.
- Описывай даже форматирование и опечатки по эффекту, например
  `fix typo in error message`.
- Не выполняй `git add`, `git commit` и не меняй рабочее дерево.
