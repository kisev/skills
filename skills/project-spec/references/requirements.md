# Профиль требований

Используй этот профиль для `specs/requirements/`. Нормативное требование по
возможности атомарно, однозначно, необходимо, непротиворечиво, проверяемо и
трассируемо; описывай требуемое поведение, не случайную реализацию. Когда это
естественно, используй форму: "Когда <событие>, <система> должна <реакция>."

ID: `REQ-F-NNN` для поведения, `REQ-I-NNN` для интерфейса, `REQ-Q-NNN` для
качества и `REQ-C-NNN` для ограничения. Существующие ID не перенумеровывай и не
переиспользуй. Перед новым ID проверь specification и доступную историю; если
безопасный номер неясен, спроси человека.

`functional/README.md`, `quality/README.md` и `constraints/README.md` содержат
все соответствующие требования. В `interfaces/README.md` есть индекс; отдельный
файл разрешён только для подтверждённой внешней поверхности, например CLI, HTTP
API, configuration или events. Не дублируй OpenAPI, JSON Schema, Protobuf и
подобные contracts: сошлись на источник синтаксиса и опиши семантику,
совместимость, ошибки и инварианты.
