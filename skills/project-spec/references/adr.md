# Профиль ADR

Создавай ADR только для архитектурно значимого решения: изменения границ
components, крупная технология или external dependency, cross-cutting mechanism,
стратегия совместимости, критичный атрибут качества либо дорогое для отмены
решение. Для bugfix, rename, локального refactoring или тривиальной реализации ADR
не нужен. Если значимость неоднозначна, спроси человека.

Используй следующий свободный номер и template `templates/adr.md`. Один ADR - один
файл `NNNN-short-title.md`. Поддерживаемые статусы: `proposed`, `accepted`,
`deprecated`, `superseded`.

ADR хранит историю решения. Не переписывай старый ADR так, будто новое решение
существовало всегда. Для замены создай новый ADR, старому установи `superseded`,
свяжи оба документа и сохрани первоначальный context.
