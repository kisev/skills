# Профиль ADR

Создавай ADR только для архитектурно значимого решения: границы компонентов,
крупная технология или внешняя зависимость, cross-cutting механизм, стратегия
совместимости, критичный атрибут качества или дорогое для отмены решение. Для
bugfix, rename, локального refactoring или тривиальной реализации ADR не нужен.

Используй свободный номер и `templates/adr.md`: один файл `NNNN-short-title.md`.
Статусы: `proposed`, `accepted`, `deprecated`, `superseded`. ADR хранит историю:
для замены создай новый ADR, свяжи документы и пометь старый `superseded`.
