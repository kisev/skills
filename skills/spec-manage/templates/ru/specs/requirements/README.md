# Требования

## Назначение

Объясните, что этот раздел содержит нормативные, проверяемые соглашения о поведении системы, интерфейсах, качестве и ограничениях.

## Включено

- Индекс четырех типов требований.
- Общие правила монотонной нумерации стабильных ID, истории жизненного цикла и прослеживаемости.
- Ссылки на машиночитаемые контракты.

## Исключено

- Структура компонентов и потоки выполнения, планы реализации, декомпозиция задач или повторение дочерних требований.

## Правила декомпозиции

Используйте только четыре обязательных каталога типов. Не создавайте новые типы верхнего уровня.

## Ожидаемая структура

```text
requirements/
├── README.md
├── functional/README.md
├── interfaces/README.md
├── quality/README.md
└── constraints/README.md
```

## Шаблон содержания

Дайте краткий индекс разделов и правила для `REQ-F-*`, `REQ-I-*`, `REQ-Q-*` и `REQ-C-*`. Укажите, что новые номера должны быть выше исторического максимума, а выведенные из действия требования сохраняются как краткие записи жизненного цикла. Удалите эти инструкции из созданного документа.
