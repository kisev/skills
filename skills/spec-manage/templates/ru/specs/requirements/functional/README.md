# Функциональные требования

## Назначение

Фиксируйте нормативное наблюдаемое поведение системы и условия его проверки.
Поведение остается тем же независимо от того, доступно ли оно через CLI, HTTP API, событие или другой транспорт.

## Включено

- Поведение пользователей и системы.
- Реакции на события и ошибки.
- Инварианты и поддерживаемые переходы жизненного цикла.

## Исключено

- Синтаксис внешней поверхности и семантика протокола, принадлежащие `REQ-I-*`.
- Цели качества, платформенные ограничения, дизайн компонентов и детали реализации.

## Правила декомпозиции

В v1 храните все функциональные требования в этом `README.md`. Не разделяйте их автоматически по функциям, доменам, сценариям использования или компонентам.

## Ожидаемая структура

```text
functional/
└── README.md
```

## Шаблон содержания

Для каждого требования используйте стабильный `REQ-F-NNN`, четкое нормативное утверждение, необязательное обоснование и проверку, если она нетривиальна. Ссылайтесь на владельцев интерфейсных требований, требований качества и ограничений вместо повторения их нормативных фактов.

```markdown
### REQ-F-001 - Повторить запрос

Когда внешний сервис возвращает 503, клиент должен выполнить не более трех попыток.

#### Проверка

- Четвертый запрос не выполняется.
```
