# 03 Context And Scope

## Purpose

Define the system boundary and its relationships with external people, systems, and trust domains.

## Included

- External subjects, users, neighboring systems, upstream and downstream dependencies, and exchanged information.
- Trust boundaries and crossings at the system boundary, with direct links to relevant `REQ-*` owners.

## Excluded

- Internal components, deployed network topology, secret placement, authorization mechanisms, and duplicated interface protocols.

## Decomposition Rules

Keep the complete context in this `README.md`; do not create child files. Use one System Context diagram only when it clarifies boundaries better than text.

## Expected Structure

Describe in-scope and out-of-scope responsibilities, external subjects and systems, interactions, exchanged data classes, and trust-boundary crossings.

## Content Template

Replace this guidance with a system boundary statement; external-subject and neighboring-system descriptions; boundary-crossing interactions; trust boundaries; and direct requirement links.
