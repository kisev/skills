# 06 Runtime View

## Purpose

Explain how target-state building blocks collaborate in architecturally meaningful runtime scenarios.

## Included

- End-to-end control and data flow, state transitions, concurrency or asynchronous behavior, failures, timeouts, retries, recovery, and completion conditions.
- Direct links to the behavior and quality requirements demonstrated by each scenario.

## Excluded

- Every ordinary use case, static component descriptions, delivery orchestration, implementation traces, and test scripts.

## Decomposition Rules

This `README.md` is the scenario index and summary. Add one file only for a meaningful end-to-end scenario that needs independent explanation; do not split by component or implementation step.

## Expected Structure

For each scenario, state the trigger, participants, ordered interactions, data or state changes, failure and recovery paths, terminal conditions, and requirement links. Use a sequence or state diagram only when clearer than prose.

## Content Template

Replace this guidance with indexed target-state scenarios covering normal and material failure paths, asynchronous boundaries, recovery behavior, and direct links to provided `REQ-*` entries.
