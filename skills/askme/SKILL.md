# Вопросы для решения

## Граница

- Не меняй репозиторий, внешние системы, документы или состояние задачи.
- Сначала самостоятельно проверь факты, доступные в текущем репозитории и
  переданном контексте. Не спрашивай пользователя то, что можно установить
  проверкой.
- Пользователь принимает решения. Не действуй по неполным ответам и не выдавай
  предположение за согласованное решение.
- Не создавай документ, артефакт, GitLab-объект или план публикации. При
  использовании из `task-prepare` сначала нужно согласовать смысл задачи, а
  затем переходить к его workflow.

## Интервью

1. Определи цель, известные факты, решения, неизвестные и зависимости между
   ними. Построй дерево решений, а не линейный список вопросов.
2. До первого вопроса покажи в чате блок **Предполагаемая задача**: проблема,
   ожидаемый результат, границы, критерии приемки и неизвестные. Это гипотеза,
   которую пользователь может подтвердить или исправить.
3. Составь текущую границу: все независимые вопросы, чьи предпосылки уже
   известны. Не задавай одновременно вопрос и зависящий от него вопрос.
4. Проведи один логический раунд через штатный интерактивный инструмент host.
   Если у host нет такого инструмента, задай вопросы в чате. Каждый вопрос
   содержит одну мысль, нужный контекст и, когда это уместно, рекомендуемый
   вариант. Для правил сочетания option и свободного ввода прочитай
   `references/question-guidelines.md`. Если фактов достаточно, задай только
   вопрос о подтверждении предполагаемой задачи.
5. После ответа обнови дерево и переходи к следующей границе. Остановись, когда
   достигнуто общее понимание либо остался blocker, который нельзя закрыть
   доступными фактами.
6. Заверши кратким итогом: принятые решения, открытые вопросы, риски и следующий
   подходящий workflow. Не запускай отдельный workflow без нового запроса
   пользователя. Исключение: если `task-prepare` вызвал это интервью,
   подтверждение предполагаемой задачи разрешает ему продолжить текущий workflow,
   но не создавать или изменять GitLab-задачу.

## Preset `questionnaire`

Если первый аргумент - `questionnaire`, подготовь черновик вопросов только для
чтения для другого получателя. Сначала выясни его роль, контекст и решения или
факты, которые нужны пользователю. Расположи вопросы по приоритету, сохрани одну
мысль в вопросе и объясни причину, когда без нее вопрос неоднозначен. Не записывай
файл.

## Composition-protocol

- При конфликте рекомендаций: safety/confirmation > явный запрос пользователя > pipeline > layering.
