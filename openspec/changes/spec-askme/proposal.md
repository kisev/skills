# Proposal

## Why

askme — core skill confirmed in the foundation renegotiation (see
`renegotiate-foundation`): frequently used and staying. This change gives
the component its exhaustive specification and executes the rework items
the owner accepted in this change's audit round. The current behavior is
the baseline; the audit found four text-consistency defects against the
shared canon and one behavioral corner the owner chose to fix.

## What Changes

The exhaustive contract captures askme as implemented — activation by
invited clarification, the read-only interview boundary with evidence-first
discipline, cumulative statement rebuild, dependency-bounded rounds, the
cumulative closing boundary, continuation semantics, the two-mode
invocation boundary, review-candidate necessity, the `questionnaire`
preset, composition and premortem rules, and portable surfaces.

Owner-accepted fixes from the audit:

1. Round independence follows the shared canon: a prerequisite precedes its
   dependents; independent questions are not serialized behind it (workflow
   wording today over-serializes).
2. The premortem prose moves to the shared necessity doctrine, leaving a
   one-line delegation in askme and goal — three drifting formulations
   collapse into one canon beside the machine contract.
3. The recommendation-conflict order (safety and confirmation > explicit
   user request > pipeline > layering) moves from askme's local
   "Composition Protocol" into the shared question guidelines, where every
   interviewing skill reads it.
4. The duplicate necessity section in the workflow is removed; the step-one
   delegation already carries it.
5. Ambiguous invocation context gets one bounded mode clarification
   ("explicit or internal?") instead of a bare stop — consistent with the
   skill's own contradiction doctrine.

## Capabilities

### New Capabilities

- `askme` — the exhaustive interview specification drafted in this change.

### Modified Capabilities

None.

## Impact

`skills/askme` (workflow text), `skills/goal` (premortem delegation),
`shared/references/necessity-doctrine.md` and
`shared/references/question-guidelines.md` (hoisted canon),
`shared/manifest.json` (goal gains the necessity-doctrine destination), and
`openspec/specs/askme/` created on archive. The legacy
`specs/capabilities/{skills,commands}/askme.md` retirement stays in
`renegotiate-foundation`.
