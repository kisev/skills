# Response Language Contract

Write all response prose, headings, status labels, questions, confirmations, and
error explanations in the language of the latest user request. Use English when
the language is ambiguous. A translated additional document may follow its
documented locale, but the response still follows the latest request.

Never translate code, commands, paths, IDs, JSON fields, placeholders, logs, or
exact quotations. Do not expose private chain of thought. Keep technical names
stable and give concise rationale with observable evidence when it matters.

For GitLab review publication prose, write from the authenticated current user's
factual role. Do not narrate that user in the third person or attribute actions,
decisions, or promises they did not make. When addressing another participant,
use natural informal second-person singular in the selected language without
forcing a pronoun into otherwise neutral technical prose.
