# Постоянный тестовый стенд Mattermost

[English](README.md)

Стенд автоматически проверяет `mattermost` и `mattermost-triage` на настоящем
сервере Mattermost. Окружение сохраняется между прогонами и не входит в архивы
навыков и обычный `task check`. Нужны Linux, Docker Engine, Compose v2
с поддержкой `up --wait`, OpenSSL и инструменты Mise. Образы и браузер
скачиваются только при необходимости.

## Первый и повторные запуски

Из корня репозитория:

```sh
task mattermost:config
mise install
mise exec -- agent-browser install
task mattermost:test
```

По умолчанию задачи используют отдельную команду `docker-compose`. Для плагина
Docker CLI добавляйте `COMPOSE="docker compose"` к каждому вызову задачи.
Команды также можно запускать напрямую через
`docker compose -f apps/mattermost-test/compose.yml`.

Задача собирает навыки, запускает контрактные и регрессионные тесты, поднимает
стенд, создаёт или переиспользует свои аккаунты, команду, каналы, личные и
групповые чаты, сообщения и изолированную авторизацию. Повторяйте ту же команду:
ручная регистрация, ввод токенов, отправка и проверка скриншотов не нужны.
`task mattermost:init` инициализирует окружение без тестов и выводит URL
свободной зоны. `task mattermost:up` только запускает контейнеры.

Адрес по умолчанию - `https://localhost:8443`. Тесты проверяют TLS через локальный
CA; изолированная сессия Chromium привязана к проверенному открытому ключу
сертификата сервера. CA bundle процесса включает системные корни и тестовый CA,
поэтому запуск браузерного инструмента и подключения к провайдеру работают.
Системное доверие, существующий профиль браузера и проверка сертификатов
в навыках не изменяются. Для своего браузера можно экспортировать публичный CA
командой `task mattermost:ca` и импортировать вручную. Закрытый CA остаётся
в Docker. В URL используйте `localhost`, не `127.0.0.1`: это имя сертификата.

По умолчанию используется `mattermost/mattermost-team-edition:10.10.3`, доступная
фиксированная патч-версия ветки 10.10. При подготовке стенда в официальных
репозиториях Team и Enterprise не было тега `10.10.19`. Это не подтверждает
совместимость с точной патч-версией рабочего сервера. Доступный подходящий образ
можно задать через `MM_TEST_IMAGE`. `MM_TEST_PORT` меняет локальный HTTPS-порт
(по умолчанию 8443), `MM_TEST_PROJECT` изолирует ресурсы Compose
(по умолчанию `mattermost-cards`). Сохраняйте эти значения для последующих
команд. Не подключайте старую версию к данным, мигрированным
новым сервером: используйте другое имя проекта.

## Состояние и принадлежность данных

Именованные volumes сохраняют данные сервера и CA. Локальное состояние проекта
находится в `.build/mattermost-test/<project>/state/`, отчёты - в соседней
`reports/`. Сгенерированные credentials находятся в приватном `fixtures.json`:
не копируйте их в чат, аргументы команд или Git. Навыки получают изолированные
XDG-пути. Отчёты и скриншоты содержат только тестовые данные и не входят в Git.

Идентификаторы фикстур и команды стабильны; тесты управляют своими именованными
каналами и сообщениями. Канал `free` предназначен для ручных экспериментов и
не перезаписывается обычными проверками. Тестовые публикации добавляют примеры
в тестовые каналы. Блокировка запрещает одновременные операции над одним
проектом. Проект Compose из другого checkout отклоняется: выберите другое
значение `MM_TEST_PROJECT` и порт вместо перехвата чужого окружения.

## Покрытие и результаты

| Область | Доказательства |
| - | - |
| Чтение | Реальная пагинация по 205 фикстурам, треды, личные/групповые чаты, участники, реакции, периоды, продолжение transcript |
| Авторизация и кеш | Реальная браузерная авторизация, отсутствие credentials, отказ для приватного канала, попадание в кеш/очистка, refresh и частичный read-many |
| Публикации | Реальные POST текста/файла/карточки, идемпотентный повтор и восстановление через GET после имитации потерянного ответа |
| Триаж | Реальный сбор, отклонение неверной цитаты, артефакты, публикация ответа, инкрементальная граница и перенос незакрытых пунктов |
| Карточки | Стандартные/кастомные RU/EN, обычный вид и узкий тред, значения возле лимита и заведомо слишком большой контрольный пример |
| Жизненный цикл | Повторная инициализация, сохранность свободной зоны и отдельный тест сброса |
| Сбои | Переносимые unit-тесты проверяют повреждённое состояние, таймауты, устаревшие/подменённые действия, неоднозначную загрузку и частичные ответы |

Каждая проверка реального сервера сохраняет статус и доказательства в
`result.json` с временной меткой; `reports/latest.json` указывает на него.
Браузерные проверки сверяют содержимое, сворачивание и переполнение, сохраняют
скриншоты. Ошибка проверки возвращает ненулевой код. Таймаут считается ошибкой,
а не пропущенным успехом. Локальный тестовый сценарий может исполнять helpers
публикации для собственных фикстур; при этом
[обычная публикация через навык](../../skills/mattermost/references/workflow.md#publication)
остаётся ручной. Примеры и лимиты описаны в
[гайде карточек](../../skills/mattermost/references/cards.md).

## Отдельный уровень с реальным агентом

```sh
EVAL_HOST=opencode EVAL_MODEL=provider/model EVAL_TIMEOUT=300 \
  EVAL_MAX_TOKENS=12000 EVAL_MAX_COST=1 task mattermost:live
```

Задайте реальные значения и авторизацию провайдера до запуска. Поддерживаются
`opencode` и `codex` через существующие host-адаптеры репозитория. Ключи
провайдера явно передаются стандартными переменными окружения; OpenCode также
получает `OPENCODE_CONFIG_CONTENT` и `OPENCODE_CLI_CONFIG_CONTENT`. Настройте
там неинтерактивные permissions хоста. Глобальные credentials и конфигурация
хоста не копируются. Нужны установленный CLI и настроенный провайдер.
Отсутствие настроек обнаруживается до запуска стенда.

Live-workspace сохраняется внутри состояния проекта. Реальные навыки должны
прочитать точную фикстуру, подготовить артефакты триажа и план карточки,
сохранив ручную границу отправки. Сценарий проверяет артефакты, а не заявление
модели об успехе. Сохраняются очищенный вывод хоста, usage, стоимость и проверки
бюджетов. Учёт соответствует существующему eval runner: таймаут ограничивает
выполнение, токены и стоимость проверяются по полученной телеметрии после
запуска, это не предоплаченный лимит расходов. Без телеметрии токенов/стоимости
результат неполон и не проходит проверку. Детерминированному уровню модель
и credentials провайдера не нужны.

## Явное пересоздание

```sh
task mattermost:reset
MM_RESET_CONFIRM=the_preview_digest task mattermost:reset
task mattermost:test-reset
```

Первая команда только показывает точные ресурсы проекта и digest. Подтверждённая
команда удаляет volumes этого сервера, свободную зону, credentials, локальное
состояние навыков и тестовую браузерную сессию, затем инициализирует всё заново.
Отчёты сохраняются. Изменённая область, чужой проект, неожиданные volumes и
симлинки в состоянии отклоняются. Тест сброса использует собственный временный
проект со случайным именем и проверяет сохранность основного стенда и отчётов.
Обычный прогон никогда не сбрасывает стенд.

## Остановка и диагностика

```sh
task mattermost:logs
task mattermost:down
```

Down сохраняет именованные volumes: аккаунты, сообщения, база и CA остаются.
Если запуск завершился по таймауту, проверьте
`docker compose -f apps/mattermost-test/compose.yml ps`. Занятый порт можно
заменить через `MM_TEST_PORT`; вместо отсутствующего плагина Compose можно
использовать отдельную команду. Сразу после первого запуска экспорт сертификата
может потребовать повтора, пока Caddy создаёт локальный CA.

Это локальный тестовый стенд: только HTTPS привязан к `127.0.0.1`; PostgreSQL
не имеет порта на хосте и использует беспарольный trust во внутренней сети.
Почтовые уведомления, телеметрия и плагины отключены. Healthcheck использует
встроенную команду `mmctl --local system status` через Unix-сокет внутри
контейнера; образу Mattermost не нужны shell или curl.
Необязательный Python driver создаёт фикстуры через тот же приватный сокет;
это не публичный API-сервис. Не используйте стенд как общий или рабочий сервер.
При ошибке изучите отчёт и `task mattermost:logs`, исправьте причину и повторите
прогон. Не удаляйте постоянное состояние лишь ради прохождения теста.
