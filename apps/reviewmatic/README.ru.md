# reviewmatic

[English](README.md)

`reviewmatic` — механический вспомогательный рантайм навыка `mr-review`. Он
собирает один GitLab merge request только для чтения, собирает ограниченный
фон для OCR, запускает движок OpenCodeReview, сравнивает сессии, проверяет
свежесть головы, загружает профили ревью и генерирует команды черновиков
GitLab. Он никогда не оценивает содержимое и не меняет GitLab.

## Команды

- `collect` — точный сбор только для чтения с полнотой и редактированием
  секретов.
- `background` — фон в лимите 8000 байт, задача первой, сокращения раскрыты.
- `ocr-runs` — один процесс OCR на алиас, параллельно.
- `ocr-compare` — группы новые, сохраняющиеся, решённые, непросмотренные.
- `revalidate` — свежесть головы относительно снимка.
- `profiles` — эффективный профиль и проверка провайдеров.
- `drafts` — проверка головы и shell-блок черновиков GitLab.
- `runtime-info` — версия и разрешённый коммит установки.

## Запуск из Git через uvx

Используйте тот же канал исходников, что и у установленного навыка. Стабильные
навыки используют точный тег выпуска (`vX.Y.Z`), развивающие — ветку `dev`:

```shell
REVIEWMATIC_REF='<ref>'
uvx --from "git+https://github.com/kisev/skills.git@${REVIEWMATIC_REF}#subdirectory=apps/reviewmatic" reviewmatic runtime-info
```

`uvx` создаёт временное окружение; `uv tool install` и публикация в PyPI не
нужны. Обновляйте кэш исходников флагом `--refresh-package reviewmatic`, если
выбранный ref изменился. `uv cache clean` удаляет исполняемый файл, но не
черновики и `runbook.md` в приватном каталоге состояния. `git`, `glab` и
внешний CLI `ocr` (минимум 1.13.6) — внешние зависимости рантайма.

## Профили

Алиасы ревьюеров живут в `~/.reviewmatic/reviewers.json` и
`./.reviewmatic/reviewers.json`; локальный файл перекрывает глобальный по
алиасу и умолчанию. Профиль хранит `alias`, `provider`, `model` и `effort`, но
не секреты.
